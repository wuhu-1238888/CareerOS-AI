# CareerOS AI 前端开发规范(DesignRules)

> **文档定位**:本文件是 Claude Code 前端开发的**硬约束清单**,在编写任何组件/页面前必读,提交前逐条自检。
>
> **与 DesignSystem.md 的关系**:[DesignSystem.md](./DesignSystem.md) 定义"系统是什么"(token、组件规格、布局体系);本文件定义"开发时什么必须做、什么禁止做"。token 值以 DesignSystem.md 的 front matter 为唯一事实来源;本文件的禁止项具有最高优先级。
>
> **铁律**:颜色、字号、间距、圆角、阴影只允许引用 DesignSystem.md front matter 的 token,禁止硬编码新值。需要新值 → 先改 DesignSystem.md,再使用。

## UI原则

### 1. 专业 SaaS 风格

CareerOS AI 的界面读起来应该像一款**值得信赖的职业工具**(对标 LinkedIn、知乎职场、Notion 级别的克制),而不是一个"AI 玩具"。

- 布局有秩序:页面解剖学固定(顶栏 64px → 居中容器 1160px → 页面头 → 内容区),任何新页面不得发明新骨架。
- 视觉克制:白/暖纸底 + 1px 分隔线 + 轻阴影,层级靠字重与间距,不靠颜色与特效。
- 交互有边界:所有可交互元素有明确的 hover / focus / disabled / loading 态;focus 环(2px `green-600`,2px 偏移)不可移除。
- 状态有语义:状态永远「颜色 + 文字」双通道(`badge-success`「已完成」),禁止裸色点作为唯一信号。
- 数据视图四态齐全:内容 / 空 / 加载(骨架屏)/ 错误(重试入口),缺一不可。

### 2. 避免过度 AI 视觉

AI 是 CareerOS 的**能力,不是主题**。界面的主角是用户的职业成长数据,不是"AI 感"。

**允许的 AI 视觉(全部清单,不在此列的都不允许)**:

| 元素 | 位置 | 规格 |
|---|---|---|
| `ai-badge` | AI 生成内容的标签 | 紫色 pill + ✦ 图标 + 「AI」文字(DesignSystem `ai-badge` token) |
| `ai-insight` | AI 解释/分析块 | 紫底 + 左侧 3px 紫边(DesignSystem `ai-insight` token) |
| Agent 状态 | Agent Card 上 | 「分析中」badge + 16px spinner |
| 分析过程反馈 | AI 任务执行时 | 进度条 + 文案轮播(如"正在理解你的背景…") |

**AI 视觉的使用纪律**:

- 紫色(`violet-*`)全站只服务于"这是 AI 说的"这一个语义。用户自己的内容、导航、装饰一律禁用紫色。
- 每个 AI 徽章都必须对应真实的 AI 输出;禁止为了"显得智能"给静态内容贴 AI 标签。
- AI 输出必须渲染为**结构化组件**(卡片、列表、图表、对比块),禁止输出大段未加工文本。

### 3. 信息优先

- 每个页面 2 秒内传达核心信息:你是谁、进展如何、下一步做什么。
- 大数字(匹配度、进度)用 `{typography.num}` 32px/700 渲染,是页面的视觉锚点。
- 装饰性元素(插画、图形)只允许出现在空状态,且 ≤180px;其他位置出现装饰即为违规。
- 渐进披露:先摘要后细节;一屏只呈现决策所需信息,其余折叠/进入下层。
- 每屏一个主行动(40px 主按钮),放在页面头右侧。

## Component规则

### 按钮

| 规则 | 内容 |
|---|---|
| 层级 | `button-primary`(绿 600,每屏最多 1 个)→ `button-secondary`(白底描边)→ `button-ghost`(绿字)→ `button-danger`(红底,仅删除/不可逆操作) |
| 尺寸 | 高度 40px,圆角 8px,文字 14px/500;图标按钮 40×40 |
| 文案 | 动词开头、≤8 个中文字、无句号:「创建画像」「上传简历」「重新生成」;禁止「提交」「确定」类空泛词 |
| 状态 | hover(green-700)/ pressed(green-800)/ disabled(白底 42% 文字)/ loading(spinner 替换文字,禁双提交)四态必须实现 |
| 禁止 | 渐变按钮、发光按钮、彩虹按钮、胶囊按钮(胶囊只属于徽章/标签)、按钮堆叠(>2 个同级按钮说明动线未收敛) |

### 卡片

| 规则 | 内容 |
|---|---|
| 规格 | 白底 + 1px `hairline` + `shadows.card` + 圆角 16px + 内边距 24px(引用 `card` token) |
| 内容 | 一张卡片一个想法:标题(h3 16px/600)+ 内容 + 可选底部动作(ghost 链接);多想法拆卡或用 24px 分隔 |
| 交互 | 仅可点击卡片 hover 上浮(`shadows.hover`);静态卡片 hover 无任何变化 |
| 色彩 | 卡片底永远是白色;语义色(红/黄)只出现在徽章、横幅、图表,禁止整卡染色 |
| 四态 | 数据卡片必须实现内容/空/加载/错误四态;空态 = 卡片内 Empty State,不是空白 |

### 导航

| 规则 | 内容 |
|---|---|
| 结构 | 顶栏 64px:logo 左 → 6 个一级入口(工作台 / 职业画像 / 成长路线 / 岗位匹配 / 简历优化 / 模拟面试)中 → 主 CTA + 头像右;白底 + `hairline` 下边线,sticky |
| 状态 | 当前入口:14px/500 `ink` + `green-600` 文字或 2px 下划线;未选中:`ink-muted`;hover:`ink` |
| 约束 | 不引入侧栏、不引入 mega 菜单、不引入二级导航抽屉;6 个入口已足够,加东西先改产品决策 |
| 响应式 | <768px 入口折叠为汉堡 + 抽屉;头像与 CTA 永远可见 |
| 禁止 | 图标堆砌导航(图标仅辅助文字,不许只有图标);导航底色走 `bg-surface`/`border-hairline` token,深浅色自动适配,禁止硬编码深色/渐变导航 |

### Dashboard(工作台)

回访用户的主页,组合规则如下:

- **结构顺序**(从上到下;三大核心区回答四问:当前状态 / 下一步做什么 / AI 发现了什么 / 成长有没有变化):
  1. 问候行:用户名 + 今日状态一句话(「本周完成 3 个任务,路线图进度 42%」)+ 画像过期提示
  2. 「下一步建议」行动卡:green-50 底 + 左绿边横幅(复用简历分析页「建议采纳」视觉),基于真实业务状态规则链首个命中(完成画像 → 完善目标岗位 → 生成路线图 → 优化简历 → 继续任务);全部完成 → 中性文案无 CTA;不引入 AI 推荐系统。视觉层级:眉标 12px/600 绿 + 标题 16px/600 + 说明 14px + 单个主 CTA(明显但克制,无复杂装饰)
  3. KPI 行:3 个 Stat Card(岗位匹配度 / 路线图进度 / 待处理建议),大数字 + 提升/下降徽章;待处理建议 = 最近工作简历最新优化版本的 pending 建议数,无简历/无版本 → 「—」(不伪造 0)。「本周任务」卡已随 IA 重构删除(weekTasks 数据仍供问候行一句话状态)
  4. AI 洞察(回答「AI 发现了什么」):单张分析摘要卡 = 最近一次画像分析 top-3 摘要(岗位优势 ✓ 绿 / 当前短板 中性图标无红、带方向来源前缀 / 推荐行动 → 绿,各取前 3 条);标题 text-h2 + ai-badge + 副标题;底部 ghost「查看完整分析」→ `/profile#glance`(仅已分析且有合法数据时显示);数据源 profile.get 的 aiAnalysis 客户端解析,不混入岗位匹配报告;未分析/解析失败 → 卡内引导(去完成画像/去画像页),不伪造 AI 结论;分析导向:只呈现 AI 原文,不添加「建议你…」命令式措辞(与「下一步建议」分工)
  5. 成长趋势(回答「成长有没有变化」):画像版本 / 最新匹配度 / 近 8 周 sparkline + ghost「查看完整报告」→ `/dashboard/growth`
- **规则**:首屏组件 ≤7 个;每个组件四态齐全;新用户空态 = 引导完成画像(主 CTA「开始职业探索」);任何数据变化显示「较上次」增量徽章;工作台不再渲染顾问卡与「我的工作」模块卡(与顶部导航重复的入口已移除,功能/路由/业务逻辑全部保留)
- **禁止**:把工作台做成聊天窗口;把 Agent 拟人化为卡通形象;堆砌 6 个以上的仪表盘小部件;出现与用户无关的"平台公告"式内容;伪造 AI 分析/成长/匹配数据(数据不足 → 降级引导)

## 深色模式规则(任务 6.9)

> 深色值表唯一事实来源 = DesignSystem.md front matter `darkColors:`。实现机制:CSS 变量 `--careeros-*`(存「H S% L%」三元组)+ `<html>.dark` 类切换;业务组件类名零改动。

| 规则 | 内容 |
|---|---|
| 换肤范围 | 只有主题相关 token(canvas/surface/sunken/hairline×2/ink×4/green-50·100/violet-50/语义色 8 个)经 CSS 变量;green-400~800 / violet-400·700 / chart.* / boxShadow 两主题一致,禁止另行变体 |
| 对比度 | 两主题下所有文本/背景组合 ≥4.5:1;语义徽章(成功/警告/危险/信息)在深色叠加面上必须逐项验证;白色文字只允许配静态深色(green-600/700/800 按钮),不允许配深色变体的亮红等浅色语义色(白字对 `#f87171` 仅 2.77:1) |
| 四态两主题 | 任何组件的内容/空/加载/错误四态必须**在深浅两个主题下都验证**(dev/tokens 页「深色渲染效果」区 + 浏览器切主题走查) |
| 硬编码禁止 | 深色适配禁止写第二套色值/暗色判断逻辑——一律走 token 类名自动切换;SVG 图表(Recharts)的 grid/tick 色经 `use-token-color` hook 读取,禁止硬编码灰值 |
| 主题状态 | 三态(跟随系统/浅色/深色)入口 = 顶栏头像菜单「外观」组 + 设置页「外观」卡;状态存 `localStorage careeros-theme`,system 态跟随 `prefers-color-scheme`;`<html>` 加 `suppressHydrationWarning` + 首屏防 FOUC 内联脚本 |
| 分享卡 | 分享卡片是「节点轨迹」品牌元素允许的三处场景之一(DesignSystem 品牌标识概念);卡片截图在浅色底渲染,不使用深色变体 |
| 文档同步 | 新增/修改 token 先改 DesignSystem.md front matter(含 darkColors),再改 globals.css 与 tailwind.config |

## 页面规则

> 每页按固定格式约束:页面目标 → 必备区块 → 页面专属禁令。所有页面遵守:顶栏 + 1160px 容器 + 页面头(标题 24px/600 + 描述 + 主行动右对齐)。

### 首页

- **目标**:3 秒传达价值主张,把新用户送上"开始职业探索"。
- **必备区块**:
  1. 主视觉区:标题(display 32px/700,≤14 字,如「AI 帮你找到职业方向」)+ 副标题(16px `ink-muted`,≤30 字)+ 主 CTA
  2. 三模块介绍:3 张静态卡片(画像 / 路线图 / 简历),图标 + 一句话价值,无交互
  3. 轻量信任区(可选):「你的数据只用于个性化分析」一行说明
- **已登录用户**:首页直接跳转工作台,不重复展示营销页。
- **页面专属禁令**:禁止机器人形象、禁止粒子/神经网络动效、禁止自动播放视频、禁止多 CTA(整页只有「开始职业探索」一个主按钮)。

### 职业画像页

- **目标**:最小输入成本获得画像(填写 <3 分钟),结果可信可纠偏。
- **流程与必备区块**:
  1. **分步采集**:4 步 Stepper(教育背景 → 技能 → 经历 → 兴趣目标);每步 ≤5 个字段、每步标题下一句话解释「为什么需要这个信息」;必填仅学历+专业+技能,经历与目标可跳过;底部固定「上一步 / 下一步」
  2. **分析中**:Agent 卡进度条 + 文案轮播(3-10s),禁止空白等待
  3. **画像结果**:概要文字卡 → 优势/不足双列 → 能力雷达图 → 推荐方向卡(2-4 个,含匹配度大数字)→ 发展建议
  4. **纠偏入口**:页面头常驻 ghost 按钮「这不是我」;点击 → Toast「已记录,AI 将重新分析」→ 触发重算
- **页面专属禁令**:禁止输出未加工的 AI 文本墙;禁止在结果页堆 5 个以上的图表;禁止"画像准确率 99%"类虚假精确度文案;纠偏后禁止立即清除用户已输入的数据。

### 岗位匹配页

- **目标**:粘贴目标 JD 即获得可解释的匹配度结论与投递建议;技能分析(6.4)作为匹配报告内流程共用本入口,不新增导航项。
- **流程与必备区块**:
  1. **JD 输入**:粘贴 Textarea(≤8000 字,字数提示),主行动「开始匹配」;无画像用户先见引导卡「先完成画像」(禁提交)
  2. **分析中**:与画像页相同的 Agent 过程反馈(岗位匹配顾问)
  3. **匹配报告**:①Hero 匹配度大数字(text-num)+ 建议徽章(建议投递·绿/建议补课后投递·琥珀/不推荐·红,颜色+文字双通道)+ AiBadge ②逐项对比列表(达标/接近/不足徽章 + 直接/间接/可迁移标签 + 用户证据,差距条附「这个要求我其实满足」ghost 纠偏)③用户 vs 岗位要求双线雷达(用户绿/岗位紫)④隐性需求揭示(ai-insight 视觉)⑤投递建议卡;页内唯一主行动「生成 90 天提升计划」(已生成后变「查看 90 天提升计划」)
  4. **纠偏**:逐项弹窗(只读要求 + ≤200 字说明)→ 服务端以纠偏反馈重匹配 → 更新报告
- **页面专属禁令**:禁止编造证据(每条映射必须附画像/简历出处);禁止无画像时伪造匹配结果(降级为仅拆解不匹配,建议为空);禁止输出未加工的 AI 文本墙;禁止把匹配度渲染为百分比以外的虚假精度。

### 技能分析页(matching hub 视图态,6.4)

- **目标**:从匹配报告的差距清单一键生成 90 天提升计划,无需重复输入。
- **流程与必备区块**:
  1. **教练设置**:目标岗位(预填 JD 标题)、每周投入小时(与 Navigator 对齐)、学习偏好;主行动「生成 90 天提升计划」
  2. **分析中**:Agent 过程反馈(技能教练)
  3. **教练计划**:①差距优先级矩阵(P0/P1/P2 徽章,红/琥珀/灰)②90 天时间线(视觉复用路线图:sticky 概览带 + 纵向时间线节点三态 + 周卡折叠 + 任务行三态符号)③资源卡网格(free/paid 徽章,免费置前)④里程碑/风险 ⑤ghost「返回匹配报告」
- **页面专属禁令**:禁止推荐付费课程(免费优先,付费必须标注);禁止周计划超出每周投入时间预算;禁止生成超过 13 周的"90 天计划"(13 周 = 91 天覆盖验收口径)。

### 简历分析页

- **目标**:让用户理解每处修改(可解释),自主控制采纳(可接受/拒绝)。
- **流程与必备区块**:
  1. **上传**:拖拽区(PDF/Word,40px 主按钮「上传简历」)+ 格式与隐私说明(12px);失败时 Banner 说明原因与重试
  2. **解析核对**:解析结果结构化展示(教育/技能/经历分区),支持逐项修正——AI 可能识别错,必须给用户确认机会
  3. **选择目标**:目标方向选择器(画像推荐方向优先 + 自定义输入)
  4. **优化对比**:每条修改一张对比卡——修改前(灰底引用块)/ 修改后(`green-50` 底 + 左绿边)/ 折叠的「为什么这样改」(`ai-insight` 紫块)/ 独立「接受」「拒绝」按钮,操作可撤销;AI 建议区标题行:已采纳计数 + 「全部接受」(secondary,点击先确认、确认后才应用)
  5. **ATS 评分**:大数字 + 等级文字双通道(≥80 优秀·绿 / 60-79 良好·琥珀 / <60 需改进·红)
  6. **导出**:最终文本预览区右上 —— [复制最终文本] secondary + [导出 PDF] primary(应用内 PDF 预览浮层)
  7. **版本管理**:顶部版本选择器常显(单版本亦显示「第 1 版 · 日期 · 方向」);下拉菜单 = 全部版本列表(当前版本带 ✓ 指示置顶,点击切换/回最新)+ 分隔 + 版本管理区 —— 「＋ 另存为新版本」(先确认,确认后基于当前版本创建独立副本并跳转最新版本,当前版本不变)/「删除当前版本」(危险色菜单项但不过度突出,点击先弹确认框,确认后级联删除该版本建议并自动切换剩余版本;仅剩一个版本时禁用,不得误删最后一份;原文与其他版本不受影响)
- **页面专属禁令**:禁止自动应用全部修改;禁止覆盖用户原始简历(原文永远保留);禁止"一键智能优化"类黑箱话术——每条修改必须有解释;禁止在对比视图中把修改前文本标红删除线。

### 简历优化页「我的简历」Tab(原简历中心)

- **目标**:一个页面看全、管好全部简历;多份简历并存互不干扰。
- **布局约定**(2026-09 修订):核心内容区**复用全局 1160px 内容容器**(与工作台/画像/路线图/匹配/简历优化同宽,禁止页级再收窄——已移除历史遗留的 860px 特例);「我的简历」卡 = 页头(标题 + 说明 + 「新增简历」主按钮)+ 文件列表;列表每行 = 左侧文件信息(图标 + 文件名 truncate + 大小 · 日期一行 caption,**flex-1 占满剩余宽度**)+ 右侧操作按钮组(继续优化/查看/下载/删除,间距 gap-2 靠右不因变宽而散开),整行垂直居中;窄屏按钮组换行不溢出、无横向滚动。

### 职业路线页

- **目标**:让"成为 XX"变成看得见的阶梯,并且每一级都可执行。
- **流程与必备区块**:
  1. **选择目标**:方向选择(画像推荐 + 自定义)+ 每周可投入时间 + 当前阶段自评
  2. **生成中**:与画像页相同的 Agent 过程反馈
  3. **路线图主视图**:纵向时间线——概要条(sticky:「从 X 到 Y 的 N 个月路径」+ 总进度)+ 3-4 个阶段卡(阶段名 / 时长 badge / 任务进度 badge),阶段卡展开显示:阶段目标、学习内容(Tag 列表)、实践项目(含产出物)、检查点(Checkbox 列表)、任务列表(☑ 待开始 / ◐ 进行中 / ✓ 已完成)
  4. **任务交互**:勾选切换状态可撤销;每个任务附「太难了」「已经会了」ghost 反馈按钮,点击后显示 `ai-badge` 确认并触发调整
- **页面专属禁令**:禁止横向甘特图(复杂化,违背轻盈原则);禁止一屏展示超过 4 个阶段;禁止任务完成时弹窗庆祝(用徽章与进度条内联反馈);禁止路线图页面出现课程商城式付费引导(MVP 范围外)。

### 模拟面试页(7.2/7.3)

- **目标**:基于简历 + 目标岗位的个性化面试实战:逐题作答、即时反馈,结束得到可执行的综合报告。
- **流程与必备区块**:
  1. **场次设定**:面试类型 radio(行为面/技术面/案例面,默认行为面)+ 档位 radio(短 5 / 标准 10 / 完整 15,默认短 5)+ 目标岗位(预填匹配报告岗位名);无简历先见引导卡「先上传简历」(禁提交)
  2. **出题/报告分析中**:与画像页相同的 Agent 过程反馈(「面试出题」/「面试报告」)
  3. **对话区(全站唯一特许聊天式布局,纯文字)**:面试官提问气泡(本轮新气泡打字机渲染)+ 用户答案气泡(右,绿底)+ 每题评估卡(内容/表达分徽章,数值+文字双通道 + 改进建议)+ 追问气泡与追问输入行(ghost「跳过追问」);行为面当前未作答题显示可折叠 STAR 提示;顶部「第 X / N 题」进度 + 场次信息;等待期「面试官正在思考」气泡(role=status);评估失败答案保留 +「重试评估」;**布局**(2026-09 修订):对话视图全宽继承 1160px 内容容器(与结果视图一致,原 720px 窄栏);页面单一纵向滚动(对话区不做内嵌滚动);顶部进度状态栏吸顶于顶栏下方;输入为全宽 composer 卡(rounded-card + border-hairline + bg-surface,无边框 Textarea + 底行字数与绿色主 CTA);面试官提问/追问气泡 max-w 85%、用户回答气泡 85%、评估卡全宽(sunken 底 + AiBadge 区分)、STAR 提示保持 ml-10 缩进对齐提问气泡;窄屏评估卡头部(徽章 + 评分 pill)可换行
  4. **综合报告**:Hero(场次信息 + 右上角评分摘要:内容能力/表达能力均分大数字双单元横排,每单元「数字 + 显式 / 10 + 小标签」基线对齐同行,一行动态注记「已评估 X / N 题」于下方——部分=阶段性评分、全部=面试评分已完成、0 道=仅提示暂无评分不渲染分数)→ 总体评价 → 突出优势/主要短板双卡 → 重点改进方向(ai-insight 视觉 + 「AI 建议」徽章)→ 底部 ghost「返回对话」+ 主行动「开始新面试」(确认 Dialog);已完成场次的对话为只读回顾
- **页面专属禁令**:禁止语音/视频(纯文字形态);禁止把打字机内容挂 aria-live 逐字朗读(状态播报由 role=status 承担);禁止其他页面复用聊天式布局(特许仅此页);禁止报告罗列全部问题(仅 1-2 个重点改进方向);禁止报告正文出现分数(均分为前端确定性计算,评分只在逐题评估卡内)。

## 禁止事项

### AI 视觉滥用(最高优先级)

- ❌ 不要大量使用 AI 渐变效果(紫蓝渐变、流光渐变)——全站 `linear-gradient` 使用次数应为 0;品牌绿与 AI 紫均以**纯色**使用
- ❌ 不要堆砌机器人元素:机器人吉祥物、机器人大头像、机器人问候语
- ❌ 不要做普通聊天机器人界面:左侧消息列表 + 底部输入框的类 ChatGPT 布局在本产品任何页面都不允许;AI 交互形态 = 表单 + 结构化卡片 + 内联解释,对话形态仅允许未来 Interview Agent 模块(Phase 3)单独设计——已于 2026-08-24 落地为「模拟面试页」(全站唯一特许实例,见下方页面规则与自检记录);其余页面仍禁聊天式布局
- ❌ 不要使用玻璃拟态、霓虹发光、粒子动画、神经网络连线图、3D 球体
- ❌ 不要用紫色做装饰或主题色;紫色 = AI 内容标记,仅此一义
- ❌ 不要给非 AI 生成的内容贴 AI 徽章("显得智能")
- ❌ 不要用 emoji 作为 UI 图标;图标统一 2px 描边线性风格,一套图标库

### 布局与实现

- ❌ 不要硬编码颜色/字号/间距/圆角/阴影值——一切从 DesignSystem.md front matter 引用;违规检查:`grep -rn "#[0-9a-fA-F]\{3,6\}" frontend/src` 应只出现在 token 定义文件
- ❌ 不要复制 Linear 的深色主题、Linear 的紫蓝、Atlassian 的品牌蓝或任何第三方品牌外观;CareerOS 的 token 自成体系
- ❌ 不要引入密度模式、字号缩放或"紧凑布局"切换
- ❌ 不要移除 focus 环、不要 hover-only 交互(键盘必须可达全部功能)
- ❌ 不要布局位移:骨架屏与真实内容尺寸必须一致
- ❌ 不要堆叠弹窗;多步流程在一个弹窗内用 Stepper 完成
- ❌ 不要用 `<br>`、内联 style、魔法数字拼布局;使用间距 token 与 Flex/Grid
- ❌ 不要引入 webfont(中文场景体积不可接受);使用 DesignSystem 字体栈
- ❌ 不要逐键打断式校验;校验只在失焦与提交时进行

### 文案与数据

- ❌ 不要"AI 全知"话术:禁止「精准预测」「100% 匹配」「智能生成完美简历」;AI 结论用建议口气:「我们建议…」「你可能适合…」
- ❌ 不要虚假精确度:评分只展示到个位,附等级文字与解释
- ❌ 不要在 UI 文案中堆营销形容词(「强大」「极致」「颠覆」);UI 文案 = 功能语言
- ❌ 不要把用户数据展示为"样本/演示数据"风格(匿名化示例需明确标注「示例」)
- ❌ 不要 Toast 轰炸:同一事件只发一次通知;确认类反馈内联展示(如保存后「已保存」在按钮旁)
- ❌ 不要显示裸 JSON、字段名、错误堆栈;一切后端数据渲染为人类语言
