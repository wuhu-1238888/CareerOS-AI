## 一、工作循环(11 步)

每个任务(01 文档 Stage 09 定义的四段式任务)按以下循环执行:

| 步 | 动作 | 为什么 | 输出 |
| --- | --- | --- | --- |
| 1 | **载入上下文**:读 CLAUDE.md + memory-bank 相关文档 + 实施计划当前任务 | 防止 AI 凭记忆瞎编项目规则 | 上下文就绪 |
| 2 | **明确本任务**:四段式(做什么/依赖/验证/产出物)复述给 AI | 任务边界 = 防 scope 蔓延的第一道闸 | 任务理解对齐 |
| 3 | **Plan Mode**(非平凡改动):先研究代码与文档,把方案给人过目 | 返工成本最高的时刻是「方向错了还写了 2000 行」 | 获批的计划 |
| 4 | **读现有代码与设计规则**:找可复用组件、查 DesignRules 禁令 | UI 复用防漂移;规则违反在写代码前被发现 | 复用清单 |
| 5 | **实现**:单任务单会话;遵循任务「依赖」顺序;小步连续提交 | 依赖顺序错误 = 白写(如 UI 先于数据层) | 代码 + 测试 |
| 6 | **分层测试修到绿**:按 04 文档第二节选层;失败即修,不带着红测试往下走 | 红测试会累积成返工债 | 绿测试 |
| 7 | **自检**:typecheck + lint + DesignRules 自检清单(grep 硬编码值等) | 质量门禁,全部可命令化 | 零错误 |
| 8 | **走查**:新页面真实浏览器跑一遍(桌面 + 375px) | 自动化测不出「丑」和「溢出」 | 走查结论 |
| 9 | **文档同步**:progress.md 勾选任务 + 状态行 + 偏差记录 | 文档与代码一致性靠这一步强制,不靠自觉 | 同步完成 |
| 10 | **Git**:选择性 add(不 `git add .`)→ conventional commit → push(按第五节纪律) | 单任务单 commit,历史即进度 | 提交 + hash |
| 11 | **汇报**:完成内容 + 测试结果 + commit hash + 遗留问题 | 人检查 AI 的入口(01 文档 6.3) | 汇报 |

> CareerOS 证据:步骤 1/5/9/10 来自 CLAUDE.md 标准流程;步骤 6/7 来自 implementation-plan 测试策略与 DesignRules 自检;步骤 8 来自走查期 26 个 L4 层提交;步骤 3 来自本次 SOP 任务的强制 Plan Mode 要求。

## 二、为什么(9 个「为什么」,每个都对应一个真实代价)

| 问题 | 答案 | CareerOS 代价证据 |
| --- | --- | --- |
| 为什么 Plan Mode? | 非平凡改动先研究后方案、人确认再动手;AI 一次写 2000 行再返工,比研究 20 分钟贵 100 倍 | 本 SOP 任务强制 Plan Mode;计划批准后才动文档 |
| 为什么先读 memory-bank? | 产品决策、设计约束、遗留问题都在里面;不读 = AI 用「常识」代替「项目事实」 | 决策锁定 19 项(implementation-plan v1.1)、偏差记录约定——不读就会重新质疑已锁定决策 |
| 为什么不能一次做完? | ① AI 上下文有限,长任务质量衰减;② 中间没有验收点,错误累积到不可返工;③ 人失去每次任务后的检查时机 | 任务粒度「一次独立工作会话(半天到一天)」;138 个小提交 > 13 个大提交 |
| 为什么拆阶段? | 每阶段末的验收(人走查 + 全量回归)是质量分水岭;阶段间是天然的暂停点 | 每阶段末 docs 收尾 + 703/703 验收 run;Stage 之间人拍板才进入下一阶段 |
| 为什么验收标准要可判定? | 「看起来不错」无法验收;可判定的标准是 AI 返工的唯一依据 | 04 文档第四节的坏/好例子;Task 8 用实测 px 值验收 |
| 如何减少返工? | ① 先纵后横(问题在 1 个模块修,不在 5 个模块各修一遍);② Mock 先行(无 Key 约束);③ 复杂模块留返工预算 | M2 纵向链路的 UX 问题全在横向扩展前解决;简历模块计划 7 任务实际 17 |
| 如何防 scope 蔓延? | 四层闸:四段式任务边界 → Plan Mode 计划 → git 选择性 add(审查变更)→ 明确不做清单 | CLAUDE.md「不要机械 git add .」;PRD 明确不做 10 项 |
| 如何复用已有组件? | 写代码前强制读现有组件库与 DesignRules;新 UI 优先组合已有组件;token 禁止硬编码 | DesignSystem 40 个组件 token;DesignRules「需要新值先改 DesignSystem 再使用」 |
| 如何保持文档·UI·逻辑一致? | 任务末「文档同步」是强制步骤不是建议;三处同步(计划状态行 / 技术设计补记 / progress);数字与路径定期对账 | implementation-plan 状态行模板;technical-design「实施架构决策补记」;917 vs 935 对账 |

## 三、任务四段式模板(Stage 09 产物的核心单元)

```markdown
### 任务 x.y 名称
- 做什么:不含代码的开发指令(如「新增岗位匹配 Agent,输入画像+岗位,输出匹配度与依据」)
- 依赖:显式列出(如「依赖 2.4 画像管线与 5.1 数据层」)——不可跳过
- 验证:自动测试(哪几层)+ 手工检查(走查什么)
- 产出物:代码文件 + 测试 + 文档更新

**状态:YYYY-MM-DD 已完成(commit `xxxxxxx`)。偏差记录:①…②…**
```

规则:

- 「做什么」用产品语言写,不用代码语言——写代码是执行会话的事。
- 状态行在任务完成后**当场回写**,不许攒到阶段末。
- 偏差记录:执行与计划不一致之处在此显式标注(「执行以计划为准,不回头改上游文档」)。

## 四、环境纪律(从 CareerOS 的 13 条已解决问题中抽象)

| # | 纪律 | 为什么(CareerOS 证据) |
| --- | --- | --- |
| 1 | **只跑一个 dev server** | 双 dev server 混写 .next 导致 webpack chunk 损坏(`__webpack_modules__ is not a function`) |
| 2 | **build 必须在无 dev server 时执行** | 同上,防 .next 混写致 worker 崩溃 |
| 3 | **prisma generate 前停掉 dev server** | 运行中的 dev server 锁 Prisma 引擎 DLL(Windows),generate EPERM |
| 4 | **不 kill 用户正在用的进程** | 清理遗留进程前确认归属;用户 3000 端口的 server 是用户的,不是垃圾 |
| 5 | **chunk 损坏的治愈手法**:编辑受影响路由**入口文件**触发重编译 → 验证 200 → 还原 | 只改依赖文件不触发入口重编译,病好不了 |
| 6 | **临时脚本用完即删** | 分析/裁剪/诊断脚本留在仓库 = 垃圾资产 |
| 7 | **避免日期相对锚定**(测试夹具用固定日期) | now-7 天的锚定在周一跑挂(`22e275a`) |

## 五、Git 纪律完整版(CLAUDE.md 抽象)

### 默认行为

任务完成 → 自动 commit + push,不询问。流程:git status → 检查修改内容 → 确认无敏感信息(Key/Token/Password/.env)→ 跑测试/lint/build → **逐文件选择性 add**(只加本任务相关的、确认安全的文件)→ conventional commit → push → 汇报(内容/commit/hash/push 结果)。

### 5 种必须暂停询问的情况

1. Git 冲突
2. 远端有新提交,无法安全直接 push
3. Git 命令失败且无法安全自动解决
4. 发现疑似敏感信息文件
5. 需要危险操作(force push / reset --hard / clean -fd / 删远程分支 / 覆盖历史)——**这些永远禁止未经明确允许执行**

### Commit 规范(从 138 提交观察)

- conventional commits:`feat(scope): 中文描述(任务编号)`;fix/style/refactor/docs/test/perf/chore 同理
- scope = 模块名或技术层(profile/resume/dashboard/interview/design/db/llm/ia…),与任务编号对应
- 阶段末必有 docs 收尾提交(完成表 + 遗留)
- 特殊标记:优先级(P0/P1/P2)、子任务(8.1b)、回归号(4.17)、用户反馈来源(user feedback)

## 六、汇报模板(第 11 步)

每个任务结束的汇报固定包含:① 本次完成的任务与改动 ② commit message 与 hash ③ push 是否成功 ④ 测试结果(数量 + 偶发失败说明)⑤ 遗留问题与新发现(不隐瞒)⑥ 需人工确认的事项。汇报是人的检查入口,省略任何一项都等于让检查失效。
