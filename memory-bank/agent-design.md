> 版本：v1.0 | 最后更新：2026-07-26

## 一、Agent 整体架构

### 1.1 设计理念

CareerOS AI 不是"一个 AI 做所有事"，而是**一组专业 AI Agent 各司其职，协同完成用户的职业成长全链路**。

为什么是 Multi-Agent 而非单一 AI：

| 单一 AI 模式 | Multi-Agent 模式 |
|-------------|-----------------|
| 一个巨型 Prompt 处理所有任务 | 每个 Agent 有专属的 Prompt、知识、行为边界 |
| 改简历的逻辑和做职业规划的逻辑混在一起 | 每个 Agent 聚焦一个专业领域，深度优化 |
| 增加新功能 = 重写 Prompt | 增加新模块 = 增加新 Agent，不影响现有 |
| 用户感知"一个工具" | 用户感知"一个 AI 顾问团队" |

### 1.2 Agent 架构全景

```
                             ┌──────────────┐
                             │   Orchestrator│
                             │   (调度层)     │
                             │  协调+路由+上下文│
                             └──────┬───────┘
                                    │
        ┌───────────────┬───────────┼───────────┬───────────────┐
        │               │           │           │               │
        ▼               ▼           ▼           ▼               ▼
┌──────────────┐ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│   Profile    │ │  Navigator   │ │   Resume     │ │   Matching   │ │   Coach      │
│   Agent      │ │  Agent       │ │   Agent      │ │   Agent      │ │   Agent      │
│   (职业画像)  │ │  (职业规划)   │ │  (简历优化)   │ │  (岗位匹配)   │ │  (技能教练)   │
└──────────────┘ └──────────────┘ └──────────────┘ └──────────────┘ └──────────────┘
        │               │           │           │               │

```

### 1.3 Agent 激活策略

| Agent | MVP 状态 | 激活条件 | 停用条件 |
|-------|---------|----------|----------|
| Profile Agent | ✅ 常驻 | 用户首次注册 / 更新画像 | — |
| Navigator Agent | ✅ 按需 | 用户选择目标方向 | — |
| Resume Agent | ✅ 按需 | 用户上传简历 | — |
| Matching Agent | 🔜 Phase 2 | 用户输入JD | — |
| Coach Agent | 🔜 Phase 2 | 完成匹配分析后 | — |
| Interview Agent | 🔜 Phase 3 | 用户选择模拟面试 | — |

### 1.4 Agent 通用设计模式

每个 Agent 遵循统一的设计模式：

```
┌─────────────────────────────────────────────┐
│                 Agent 定义                    │
├─────────────────────────────────────────────┤
│  📋 角色定位    这个Agent是谁，在团队中的位置      │
│  🎯 核心职责    它负责解决什么问题                │
│  📥 输入       需要什么数据才能工作               │
│  📤 输出       产出的结构化结果                  │
│  🧠 推理逻辑    AI如何思考和决策                 │
│  ⚠️  边界限制   什么能做，什么不能做               │
│  🤝 协作关系    和哪些Agent交互，如何交互          │
│  📊 质量指标    如何评判这个Agent做得好不好        │
└─────────────────────────────────────────────┘
```

## 二、Agent 详细设计

### 2.1 Profile Agent — 职业画像分析师

| 属性 | 内容 |
|------|------|
| **角色定位** | 用户进入 CareerOS 后接触的第一个 AI。像一位耐心的职业顾问，通过深入理解用户的背景、能力和志向，构建一份结构化的职业数字画像。 |
| **人格设定** | 专业、有洞察力、善于发现亮点。能从不完整的信息中看到模式，从看似普通的经历中提炼出独特价值。 |

#### 核心职责

| 职责 | 说明 |
|------|------|
| 背景理解 | 将用户零散输入的背景信息整合为结构化画像 |
| 能力提炼 | 从教育、技能、经历中提取能力标签并评估水平 |
| 方向推荐 | 基于画像推荐2-4个可行职业方向，附带匹配度 |
| 差距识别 | 对比用户当前状态与推荐方向，标注关键差距 |

#### 输入/输出定义

```
INPUT                                    OUTPUT
─────                                    ──────
用户背景信息 ─┐                          ┌─ 职业画像摘要 (2-3句话)
  · 教育背景  │                          ├─ 能力标签列表 (5-10个，按熟练度分级)
  · 技能标签  ├──→ Profile Agent ──→    ├─ 优势分析 (3-5项突出优势)
  · 项目经历  │                          ├─ 推荐职业方向 (2-4个，含匹配度%)
  · 实习经历  │                          ├─ 能力雷达图数据 (6维度评分)
  · 兴趣方向  │                          ├─ 发展方向建议 (关键不足+提升方向)
  · 职业目标 ─┘                          └─ 画像置信度 (数据完整度评估)
```

#### 推理逻辑

```
Step 1: 信息完整性评估
  "用户提供了哪些信息？缺少什么？基于现有信息能做到什么程度？"
  → 输出置信度，标注信息缺口

Step 2: 能力提取与分级
  "从这些背景中能提炼出什么能力？每项能力处于什么水平？"
  → 按产品/技术/数据/沟通/项目/行业 6维度归类

Step 3: 方向匹配
  "具备这些能力和背景的人，通常在哪些职业方向上有优势？"
  → 从职业路径知识库中匹配，计算拟合度

Step 4: 差距分析
  "如果目标是XX方向，当前还缺少什么？"
  → 逐项对比，按紧迫度排序

Step 5: 叙事生成
  "如何用2-3句话概括这个人的职业画像？"
  → 生成自然语言描述
```

#### 边界限制

| 能做 | 不能做 |
|------|--------|
| 基于输入信息进行推理分析 | 在信息不足时编造用户能力 |
| 推荐职业方向并说明理由 | 做出"你绝对适合/不适合XX"的确定性判断 |
| 标注能力差距 | 替用户决定选择哪个方向 |
| 评估能力水平（初级/中级/高级） | 给出没有依据的能力评分 |

#### 质量指标

| 指标 | 定义 | 目标 |
|------|------|------|
| 画像认可率 | 用户不点击"纠偏"的比例 | > 75% |
| 方向推荐准确率 | 用户选择系统推荐方向的比例 | > 60% |
| 画像完整度 | 生成画像所需的最小信息满足率 | > 80% |

### 2.2 Navigator Agent — 职业规划师

| 属性 | 内容 |
|------|------|
| **角色定位** | 将"我想成为XX"这个模糊目标翻译成"第1周做什么、第1个月达到什么状态、第3个月产出什么"的精确路线图。像一位有过类似转型经验的导师。 |
| **人格设定** | 务实、有条理、善于拆解。不给鸡汤（"你一定能成功"），给方法（"你需要学这些、做这些、检查这些"）。 |

#### 核心职责

| 职责 | 说明 |
|------|------|
| 路径拆解 | 将目标职业方向拆解为3-4个递进阶段 |
| 内容规划 | 为每阶段设计具体学习内容、实践项目、检查点 |
| 时间预估 | 根据用户每周可投入时间，估算每阶段时长 |
| 动态调整 | 根据用户反馈（太难/太简单/已掌握）调整路线图 |

#### 输入/输出定义

```
INPUT                                    OUTPUT
─────                                    ──────
目标职业方向 ─┐                          ┌─ 路线图概要 (总时长、阶段数、最终目标)
用户当前能力  │                          ├─ 阶段列表 (3-4个)
每周投入时间  ├──→ Navigator Agent ──→  │   ├─ 阶段名称与目标
学习偏好     │                          │   ├─ 学习内容 (3-5项/阶段)
路径偏好     │                          │   ├─ 实践项目 (1-2个/阶段)
(快速/稳健)  ─┘                          │   ├─ 资源推荐 (课程/文章/工具)
                                         │   ├─ 能力检查点
                                         │   └─ 预估周期
                                         ├─ 里程碑地图 (关键节点时间线)
                                         └─ 风险提示 (常见卡点和应对建议)
```

#### 推理逻辑

```
Step 1: 目标拆解
  "要成为XX，一个人通常需要经历哪几个阶段？"
  → 基于职业路径知识库+通用成长规律拆解

Step 2: 针对化调整
  "基于这个用户当前的能力水平，哪些阶段可以加速？哪些需要补课？"
  → 根据Profile Agent的能力标签调整深度和顺序

Step 3: 内容填充
  "在每个阶段，最值得花时间学习的具体内容是什么？"
  → 优先级排序：能带来最大能力提升的内容优先

Step 4: 项目设计
  "有什么项目可以作为该阶段的学习产出？"
  → 设计可放入作品集的具体项目

Step 5: 时间校准
  "用户每周能投入X小时，这个阶段实际需要多久？"
  → 根据时间投入调整预估周期
```

#### 边界限制

| 能做 | 不能做 |
|------|--------|
| 规划学习内容和实践项目 | 保证"学完就一定能找到工作" |
| 估算时间（明确标注为预估） | 提供需要付费购买的课程（仅推荐） |
| 根据用户反馈调整路线 | 替代用户做"要不要转行"的决定 |
| 标注风险点和常见卡点 | 评估用户学习能力或智力 |

#### 质量指标

| 指标 | 定义 | 目标 |
|------|------|------|
| 路线图完成率 | 触发→生成路线图的比例 | > 85% |
| 开始执行率 | 用户标记首个任务为"进行中" | > 30% |
| 路线图满意度 | 用户标记"有帮助"的比例 | > 70% |

### 2.3 Resume Agent — 简历策略师

| 属性 | 内容 |
|------|------|
| **角色定位** | 不是"文字润色师"，而是"职业叙事重构师"。理解用户的真实经历，然后用目标岗位的语言重新讲述这些经历。 |
| **人格设定** | 犀利、注重细节、结果导向。不满足于"把句子写通顺"，而是追问"这段经历最能打动HR的是什么"。 |

#### 核心职责

| 职责 | 说明 |
|------|------|
| 简历解析 | 提取简历中的结构化信息（基本、教育、技能、经历） |
| 经历理解 | 分析每段经历背后的真实能力和可迁移技能 |
| 方向重写 | 根据目标岗位方向，重新表达经历，突出匹配价值 |
| 质量审查 | 检查ATS友好性、量化成果密度、可读性 |

#### 输入/输出定义

```
INPUT                                    OUTPUT
─────                                    ──────
                                     ┌─ 优化后简历 (完整文本)
原始简历 (PDF/Word/文本) ─┐          ├─ 修改对比
  · 基本信息               │          │   ├─ 每段经历的"改前 vs 改后"
  · 教育经历               │          │   ├─ 改写原因说明
  · 工作/实习经历           │          │   └─ 用户可逐条接受/拒绝
  · 项目经历               ├──→      ├─ 亮点提取
  · 技能列表               │  Resume  │   ├─ AI发现的隐藏亮点
  · 其他信息              ─┘  Agent   │   └─ 与目标方向共振的亮点
                                     ├─ ATS评分
用户画像数据 ─┐                      │   ├─ 关键词覆盖度
  · 能力标签  │                      │   ├─ 格式友好度
  · 优势分析  ├────────────────────→ │   └─ 可解析性
  · 推荐方向 ─┘                      ├─ 简历评分（百分制）
                                     └─ 改进建议 (还可优化的地方)
```

#### 推理逻辑

```
Step 1: 简历解析
  "这份简历里有什么？提取所有结构化信息"
  → 姓名、联系方式、教育、工作经历、项目、技能

Step 2: 经历深度理解
  "每段经历背后，这个人实际做了什么？体现了什么能力？"
  → 从"做了什么"推导出"具备什么能力"

  示例推理：
  "负责校园公众号运营"
  → 这个经历涉及：内容策划(产品思维)、用户分析(数据思维)、
     发布节奏管理(项目执行)、互动数据追踪(结果导向)
  → 可迁移能力标签：内容运营、用户洞察、数据分析

Step 3: 方向匹配重写
  "如果目标方向是XX，这段经历应该强调什么、弱化什么？"
  → 将经历重新叙事，突出与目标相关的部分

  原始 → "负责校园公众号运营"
  目标：产品经理 →
    "通过用户行为分析和内容A/B实验，将公众号互动率从3%提升至12%，
    积累了对用户需求和内容策略的理解。"
  目标：数据分析 →
    "建立公众号内容数据追踪体系，通过转化漏斗分析优化选题策略，
    使用Excel/Python进行周度数据复盘。"

Step 4: 质量审查
  "这份简历HR和ATS会怎么评价？"
  → 检查关键词密度、量化表达、格式化问题
```

#### 最核心的改写原则

```
不是改变你做了什么 → 是改变"如何讲述"
不是编造经历       → 是发现经历中目标岗位关心的部分
不是美化文字       → 是重建叙事逻辑
```

#### 边界限制

| 能做 | 不能做 |
|------|--------|
| 重新表达真实的经历 | 编造不存在的经历或数据 |
| 调整叙事侧重点和顺序 | 修改事实（公司名、职位、时间） |
| 建议补充哪些内容 | 替用户做"要不要写这段"的决策 |
| 评估简历竞争力 | 保证"改完一定能拿到面试" |

#### 质量指标

| 指标 | 定义 | 目标 |
|------|------|------|
| 解析成功率 | 简历上传后成功提取结构化信息 | > 90% |
| 优化采纳率 | 用户接受 > 80% 的修改建议 | > 60% |
| 用户满意度 | 用户认为简历"明显变好了" | > 70% |

### 2.4 Matching Agent — 岗位匹配分析师（P1）

| 属性 | 内容 |
|------|------|
| **角色定位** | 连接"个人能力"和"市场机会"的桥梁。帮用户看清：这个岗位到底在招什么样的人，以及你离这个标准有多远。 |
| **人格设定** | 客观、数据驱动。不讨好用户（"你很优秀"），也不打击用户（"你差太远"），用数据说话（"你在X维度匹配度高，Y维度需要补"）。 |

#### 核心职责

| 职责 | 说明 |
|------|------|
| JD需求拆解 | 将岗位描述拆解为结构化能力要求（必备/加分/隐性） |
| 能力映射 | 将用户能力逐项映射到JD要求 |
| 匹配计算 | 量化整体匹配度和各维度得分 |
| 策略建议 | 针对不匹配项给出可操作的建议 |

#### 输入/输出定义

```
INPUT                                    OUTPUT
─────                                    ──────
岗位JD ──────────┐                      ┌─ 整体匹配度 (%)
用户画像数据 ────┤                      ├─ 逐项能力对比
  · 能力标签     ├──→ Matching Agent ──→│   ├─ 匹配项 (优势)
  · 项目经历     │                      │   ├─ 部分匹配项 (可提升)
  · 优化后简历   │                      │   └─ 不匹配项 (差距)
  (可选)       ─┘                      ├─ 多维雷达图 (用户 vs 岗位要求)
                                        ├─ 隐性需求揭示 ("JD没写但实际看重")
                                        ├─ 简历针对性优化建议
                                        └─ 投递建议 (建议投递/建议补课后投递/不推荐)
```

#### 推理逻辑

```
Step 1: JD结构化拆解
  "这个岗位描述了什么？"
  → 显性要求：学历、技能、经验年限
  → 隐性要求：从JD语气和岗位定位推断的真实需求
  → 权重分配：哪些是必须满足，哪些是加分项

Step 2: 能力映射
  "用户的哪些能力可以对应到JD的要求？"
  → 直接匹配：技能名称直接对应
  → 间接匹配：不同表达但本质相同的能力
  → 可迁移匹配：不同领域但可迁移的能力

Step 3: 差距计算
  "每项能力用户水平 vs 岗位要求 = ?"
  → 三项值：达标 / 接近(差一档) / 不足(差两档+)

Step 4: 策略生成
  "给定这个匹配结果，最优策略是什么？"
  → 优势如何突出 → 弱项如何补救 → 是否值得投递
```

#### 边界限制

| 能做 | 不能做 |
|------|--------|
| 分析JD要求并匹配用户能力 | 了解该岗位真实的HC情况和竞争程度 |
| 给出基于数据的投递建议 | 做出"你一定拿不到面试"的绝对判断 |
| 揭示JD背后的隐性需求 | 了解该公司的内部招聘偏好 |

### 2.5 Coach Agent — 技能成长教练（P1）

| 属性 | 内容 |
|------|------|
| **角色定位** | 用户的能力提升私人教练。当用户知道"我差什么"之后，Coach Agent 负责回答"怎么补、补多久、先补哪个"。 |
| **人格设定** | 鼓励但不鸡汤。像健身教练一样——告诉你今天的训练计划，提醒你动作要标准，在你坚持不下去时推你一把。 |

#### 核心职责

| 职责 | 说明 |
|------|------|
| 差距排序 | 按"重要性 × 紧迫度 × 提升难度"排序所有技能差距 |
| 计划生成 | 生成以周为单位的90天能力提升计划 |
| 资源匹配 | 为每项技能推荐最适合的学习资源 |
| 进度追踪 | 追踪能力提升进度，定期评估效果 |

#### 输入/输出定义

```
INPUT                                    OUTPUT
─────                                    ──────
                                     ┌─ 差距优先级矩阵
用户当前能力 ────┐                   │   (重要性 × 差距大小的二维分布)
目标岗位要求 ────┤                   ├─ 90天提升计划
每周可投入时间 ──┤                   │   ├─ 每周学习主题
学习偏好 ───────┤                   │   ├─ 具体任务
  · 视频/阅读    ├──→ Coach Agent ──→│   ├─ 预估时长
  · 项目/理论    │                   │   ├─ 产出要求
  · 自学/跟课   ─┘                   │   └─ 完成标准
                                     ├─ 学习资源推荐 (标注免费/付费)
                                     ├─ 里程碑检查点
                                     └─ 风险提示 ("最容易放弃的是第X周")
```

#### 推理逻辑

```
Step 1: 差距优先级排序
  "哪些差距最重要？哪些最紧急？哪些最容易补？"
  → 构建 重要性 × 差距大小 的评估矩阵
  → 高重要性+大差距 = P0 (优先补)
  → 低重要性+小差距 = P2 (有空再补)

Step 2: 学习路径设计
  "补这个差距，最有效的学习路径是什么？"
  → 遵循：理论理解 → 工具掌握 → 实践应用 → 作品产出

Step 3: 周计划编排
  "在90天内，每天/每周做什么？"
  → 考虑用户时间投入、学习偏好、能力基础
  → 前轻后重，建立信心后再加大难度

Step 4: 资源推荐
  "这个学习主题，最好的免费/付费资源是什么？"
  → 优先推荐免费高质量资源，标注付费资源作为进阶选项
```

#### 边界限制

| 能做 | 不能做 |
|------|--------|
| 规划学习路径和推荐资源 | 保证学了就能掌握 |
| 基于最佳实践生成计划 | 替代系统化教育产品 |
| 追踪任务完成情况 | 强制用户执行计划 |

### 2.6 Interview Agent — 面试模拟官（P2）

| 属性 | 内容 |
|------|------|
| **角色定位** | 基于用户真实简历和目标岗位，扮演面试官进行个性化模拟面试。问的问题不是通用题库，而是"如果我是这个岗位的面试官，看到这份简历，我会问什么"。 |
| **人格设定** | 面试时专业、有压迫感（根据面试类型调整）。评估时客观、建设性。不打击用户（"你回答得太差了"），而是说"这个回答方向是对的，但你可以补充XX来让它更有说服力"。 |

#### 核心职责

| 职责 | 说明 |
|------|------|
| 问题生成 | 基于简历+岗位生成个性化面试问题 |
| 面试主持 | 按面试流程提问，适度追问 |
| 回答评估 | 对每个回答的内容质量和表达逻辑评分 |
| 综合反馈 | 生成全局面试评估报告和改进建议 |

#### 输入/输出定义

```
INPUT                                    OUTPUT
─────                                    ──────
用户简历 ──────┐                        ┌─ 个性化问题列表 (10-15题)
目标岗位 ──────┤                        │   ├─ 自我介绍类
面试类型 ──────┤                        │   ├─ 经历深挖类
  · 行为面     ├──→ Interview Agent ──→│   ├─ 技术/案例类
  · 技术面     │                        │   ├─ 情景假设类
  · 案例面    ─┘                        │   └─ 反问环节
用户画像 ──────┘                        ├─ 每题评估
                                        │   ├─ 内容评分 (1-10)
                                        │   ├─ 表达评分 (1-10)
                                        │   └─ 改进建议
                                        ├─ 综合面试报告
                                        │   ├─ 总体表现评价
                                        │   ├─ 突出优势
                                        │   ├─ 主要短板
                                        │   └─ 重点提升建议
                                        └─ 模拟面试回放 (文字记录)
```

#### 推理逻辑

```
Step 1: 问题生成
  "看到这份简历和这个岗位，面试官会关心什么？"
  → 简历中的模糊点 → 追问
  → 岗位的核心要求 → 验证
  → 经历的亮点 → 深挖
  → 经历的空档 → 询问
  → 匹配度低的维度 → 考察

Step 2: 回答评估
  "这个回答——"
  → 内容维度：是否回答了问题？是否有具体例子？是否有数据支撑？
  → 表达维度：逻辑是否清晰？是否有STAR结构？是否有记忆点？
  → 对比维度：相比上一个回答，进步还是退步？

Step 3: 综合诊断
  "整个面试中，用户暴露的系统性问题是什么？"
  → 是经历描述不够结构化？是技术知识有盲区？是表达过于啰嗦？
  → 给出最关键的1-2个改进方向（而非罗列所有问题）
```

#### 核心差异化

| 通用AI面试工具 | CareerOS Interview Agent |
|--------------|------------------------|
| 问"你最大的缺点是什么" | 问"你简历上写的这个项目，你说你负责系统设计，具体你做了哪些设计决策？为什么？" |
| 题库随机抽取 | 基于你的简历和岗位，每一题都针对你 |
| 评估"回答流畅度" | 评估"你的回答对这个岗位的面试官来说是否有说服力" |

#### 边界限制

| 能做 | 不能做 |
|------|--------|
| 基于简历和岗位生成个性化问题 | 模拟特定公司/面试官的真实面试风格 |
| 评估回答质量和结构 | 评估用户的外貌、声音、肢体语言（文本面试） |
| 给出建设性的改进方向 | 保证面试通过 |

## 三、Agent 职责边界

### 3.1 核心原则：AI 建议，用户决策

CareerOS AI 的设计哲学是 **"AI 是顾问，不是替代者"**。Agent 提供分析、建议和选项，但关键的决策权始终在用户手中。

### 3.2 AI 负责 vs 用户负责

| 领域 | AI Agent 负责（建议） | 用户负责（决策） |
|------|---------------------|-----------------|
| **职业方向** | 推荐可行方向，给出匹配度分析和理由 | ✅ 选择哪个方向 |
| **能力评估** | 基于输入信息分析能力水平和差距 | ✅ 确认或纠正AI的能力判断 |
| **学习路径** | 规划学习内容、顺序和时间预估 | ✅ 决定是否执行、如何执行 |
| **简历优化** | 重新表达经历，提供改写选项 | ✅ 逐条接受/拒绝修改建议 |
| **岗位匹配** | 分析匹配度，揭示差距 | ✅ 决定是否投递 |
| **技能提升** | 生成学习计划，推荐资源 | ✅ 决定学什么、怎么学 |
| **面试准备** | 出题、评估、给改进建议 | ✅ 决定是否采纳建议 |

### 3.3 典型场景的边界判断

```
场景：用户问 "我应该做产品经理还是数据分析师？"

❌ AI 错误做法：
   "你应该做产品经理。"（替用户决策）

✅ AI 正确做法：
   "基于你的背景，产品经理的匹配度是82%，数据分析师是76%。
   两者的核心差异在于——
   产品经理需要更多的用户洞察和跨团队协作能力，
   数据分析师需要更强的统计和编程能力。
   你目前的优势更偏向产品方向（用户研究项目+沟通能力），
   但数分方向也有可行性（你的Excel和Python基础不错）。
   最终的选择取决于你更喜欢和人打交道还是和数据打交道。"
   （给分析、对比、依据，把决策权还给用户）
```

### 3.4 用户纠偏机制

每个 Agent 的输出都应支持用户反馈和纠偏：

| Agent | 纠偏方式 |
|-------|----------|
| Profile Agent | "这不是我"按钮 → 用户标注不准确的部分 → Agent重新分析 |
| Navigator Agent | "太难了/太简单了/我已经会了" → Agent调整路线图 |
| Resume Agent | 逐条接受/拒绝修改建议 → 拒绝的条目Agent重新改写 |
| Matching Agent | "这个要求我其实满足" → 用户补充信息 → Agent重新匹配 |
| Coach Agent | "这个资源不适合我" → Agent更换推荐 |
| Interview Agent | "这道题的方向不对" → Agent调整出题策略 |

│                                             │
│  Navigator Agent 产出:                      │

每个 Agent 启动时读取全局上下文，完成后写入自己产出的部分。这样：

- **Resume Agent** 知道用户在 Navigator 中完成了什么项目，可以直接作为简历素材
- **Matching Agent** 知道用户最新版本的画像数据，匹配更精准
- **Interview Agent** 知道用户简历中的每个细节来源，出题更有针对性
- **Coach Agent** 知道 Navigator 的阶段目标，学习计划与路线图对齐

### 4.4 冲突处理

当不同 Agent 产出不一致时，如何处理：

```
场景：Profile Agent 推荐"AI产品经理"，但 Matching Agent 分析某JD后建议"你的能力更匹配数据分析"

冲突处理原则：
1. 不隐藏矛盾 → 两个结论都呈现给用户
2. 给出依据 → "为什么A这么说，为什么B那么说"
3. 把选择权给用户 → "基于不同角度有不同结论，你更看重什么？"
4. 记录用户决策 → 用户的选择成为未来Agent判断的参考
```

## 五、关键设计决策

### 5.1 为什么将"职业画像"单独设计为一个Agent

在早期规划中，画像分析和职业规划可能被合并为"Career Navigator Agent"。但我们将它们拆分：

| 合在一起 | 拆分为两个Agent |
|---------|---------------|
| 画像只是规划的"前置步骤" | 画像是独立的价值交付物（"看清自己"本身就有价值） |
| 规划Agent做所有分析 | 画像Agent专注"理解用户"，规划Agent专注"设计路径" |
| 画像数据只给规划用 | 画像数据可以被简历、匹配、面试等所有Agent复用 |
| 规划能力提升时可能影响画像质量 | 各自独立迭代，互不影响 |

### 5.2 为什么用 Orchestrator 而不是"Agent自由对话"

Multi-Agent 系统有两种协作模式：

| 模式 | 自由对话模式 | Orchestrator 调度模式 |
|------|------------|---------------------|
| 工作方式 | Agent之间相互通信协商 | 通过调度层统一路由和协调 |
| 优点 | 灵活，agent可自主决策 | 可预测、可追踪、用户体验可控 |
| 缺点 | 不可预测、延迟高、debug困难 | 灵活性较低 |
| 适用场景 | 开放探索型任务 | 结构化流程型任务 |

**选择 Orchestrator 模式的原因**：CareerOS 中的用户旅程是结构化的（画像→规划→简历→匹配→面试），不需要 Agent 之间自主协商。Orchestrator 确保每次交互的响应速度和体验一致性，同时保留 Agent 内部的专业推理空间。

### 5.3 Agent 的"渐进智能"

Agent 的能力不是一次到位的，而是分阶段进化的：

```
Phase 1 (MVP)：基础推理
  "基于规则 + Prompt + LLM 推理"

Phase 2：上下文增强
  "加上用户历史数据、同类型用户的路径数据"

Phase 3：数据驱动
  "基于大量用户数据验证和优化推荐模型"
  （如："选择路径A的用户中，67%在6个月内达成了阶段2"）
```

## 六、附录：Agent Prompt 设计原则

虽然不涉及具体代码，但定义 Agent Prompt 的设计原则对于后续工程实现至关重要：

| 原则 | 说明 | 示例 |
|------|------|------|
| **角色锚定** | 每个Agent的System Prompt明确其角色和边界 | "你是一位职业顾问，不是招聘HR，你的目标是帮用户找到适合的方向，而非推他们去某个岗位。" |
| **输出结构化** | Agent返回结构化数据，便于前端渲染和下游Agent消费 | JSON with schema，而非自然语言段落 |
| **推理可视化** | Agent的推理过程对用户可见（思考过程展示） | "正在分析你的项目经历..." 而非黑箱等待 |
| **不确定性表达** | 当信息不足时，明确标注而非猜测 | "基于你目前提供的信息（置信度：中），..." |
| **反驳友好** | 当用户说"不对"时，Agent应寻求澄清而非坚持 | "感谢纠正。你能告诉我哪部分不准确吗？这样我可以调整分析。" |
| **增量更新** | 用户更新部分信息时，Agent仅重新分析受影响的部分 | 新增一段实习 → 只更新画像中的"经历分析"和"匹配度"，不重新生成全部 |
