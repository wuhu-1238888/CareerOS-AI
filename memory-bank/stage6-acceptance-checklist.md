## 一、Stage 6 实现了什么(基于实际代码核验)

总览:①**岗位匹配**——粘贴 JD → Matching Agent 拆解(显性/隐性/重要性)→ 能力映射(直接/间接/可迁移,证据必须来自画像/简历)→ 差距(达标/接近/不足)→ 双线雷达 → 投递建议;支持「这个要求我其实满足」逐项纠偏重匹配。②**技能分析**——从匹配报告一键生成固定 13 周的 90 天提升计划(优先级矩阵/周计划/里程碑/资源标注免费付费)。③**画像能力变化追踪**——最新 vs 次新版本双线雷达 + 提升/下降/新增徽章。④**简历多版本**——同份原简历多方向版本:列表/切换/复制/删除。⑤**分享卡片**——画像卡/路线图卡客户端截图下载 PNG。⑥**深色模式**——三态(跟随系统/浅色/深色),顶栏头像菜单 + 设置页入口,全站 token 换肤。

数据持久化 = 新增单表 JobMatch(每用户一行);无画像用户见引导卡、匹配降级为「仅拆解不匹配」。

## 三、具体验收步骤

> 前提:准备/使用一个有画像与简历的测试账号(账号甲);另备一个新账号(账号乙)验证无画像降级。
> 若已配置 DeepSeek Key:全步骤适用;若为 mock:步骤 S1/S2 的「成功结果」部分会走到失败分支(属环境限制),A1/A2 的 Happy Path 相应降级为遗留验证项,其余步骤(mock 或已有历史数据)照常。

### 步骤 S1:岗位匹配主链路(对应 A1)

1. 账号甲登录 → 顶栏点「岗位匹配」(成长路线与简历优化之间)→ /matching
2. 无匹配记录时显示 JD 粘贴表单:粘贴一份真实 JD(如「后端开发工程师」招聘信息,含任职要求)→ 观察字数提示(≤8000)→ 点「开始匹配」
3. 分析过程:岗位匹配顾问 Agent 卡 + 进度条 + 文案轮播 → 自动进入匹配报告
4. 报告六区块自上而下:①匹配度大数字(text-num 32px)+ 建议徽章(建议投递·绿/建议补课后投递·琥珀/不推荐·红,颜色+文字双通道)+ AI 徽章 ②逐项对比列表(每条:要求文本 + 达标/接近/不足徽章 + 直接/间接/可迁移标签 + 用户证据)③双线雷达(用户绿线/岗位紫线)④隐性需求揭示(ai-insight 紫块)⑤投递建议卡
5. 点报告内主行动「生成 90 天提升计划」→ 教练设置表单:目标岗位已预填 JD 标题、每周投入已预填(与路线图一致)→ 点「生成 90 天提升计划」→ 分析过程(技能教练)→ 教练计划页

**预期结果**:报告区块齐全、每项映射有画像/简历出处;教练计划含优先级矩阵(P0/P1/P2 徽章)、13 周时间线(周卡可展开)、资源卡(免费在前)、里程碑/风险;返回匹配报告按钮可用;刷新后数据仍在(JobMatch 落库)。

### 步骤 S2:纠偏重匹配(对应 A2)

1. 接 S1 报告页,找一条「不足」的差距项 → 点「这个要求我其实满足」→ 弹窗显示只读要求文本 + 说明输入(≤200 字)→ 提交
2. 重新进入分析过程 → 新报告

**预期结果**:纠偏后该项状态/证据回应了补充说明;不提交空说明(校验拦截)。

### 步骤 S3:无画像降级(对应 A3)

1. 账号乙(无画像)登录 → /matching → 见引导卡「先完成画像」,提交按钮禁用;点「去创建画像」→ /profile

**预期结果**:无法发起匹配;引导文案明确。

### 步骤 S4:画像历史对比(对应 A4)

1. 账号甲 → /profile,若只有 1 个版本:先「更新信息」改一项(如加一个技能)提交生成 v2
2. 最新版结果页六维雷达与推荐方向之间出现「历史对比」区:双线雷达(当前绿/上次紫)+ 能力变化列表(提升=绿底↑/下降=红底↓/新增=绿描边「新增」)
3. 版本选择器切到旧版本 → 对比区块隐藏

**预期结果**:变化徽章与两次数据差值一致;单版本/旧版本查看时区块隐藏。

### 步骤 S5:简历多版本(对应 A5)

1. 账号甲 → /resume(或简历中心)进入已有简历的结果视图 → Hero 行出现版本选择器(第 N 版 · 日期 · 方向)+「复制为新版本」+「删除版本」
2. 点「复制为新版本」→ 自动切到新版本:方向/修改建议与源版本一致,ATS 区显示「尚未评分」
3. 在新版本接受 1 条建议 → 切回旧版本 → 该条仍为待处理(互不影响)
4. 点「删除版本」→ 确认 → 版本列表减一;只剩 1 个版本时「删除版本」禁用(末版禁删)
5. 复制 → 改名目标方向?不涉及:复制版本方向与源一致(预期);导出 PDF/复制最终文本作用于当前查看版本

**预期结果**:版本独立;删除不影响原简历(简历中心原件仍在);末版禁删。

### 步骤 S6:分享卡片(对应 A6)

1. 账号甲 /profile 结果页 → Hero 区「分享画像卡」→ 弹窗出现分享卡预览(节点轨迹 + AI 徽章 + 昵称/摘要/能力标签/优势/推荐方向+匹配度/分值条)→ 点「下载 PNG」→ 浏览器下载 `careeros-画像分享.png`
2. /navigator 路线图 → 概览带「分享路线图」→ 下载 `careeros-路线图分享.png`
3. 打开下载的图片:内容与页面当前数据一致(匹配度/阶段进度/方向名)

**预期结果**:图片 560px 宽、内容一致、含「CareerOS · AI 职业成长助手」;下载失败时 toast「生成图片失败,请重试」可重试(可断网模拟)。

### 步骤 S7:深色模式(对应 A7)

1. 任意页面 → 顶栏头像 → 下拉「外观」组:跟随系统(默认选中)/浅色/深色 三态 → 点「深色」→ 页面立即变深色
2. 刷新页面 → 仍为深色(持久化,无闪白 FOUC)
3. 顶栏切「跟随系统」→ 改操作系统主题(Windows 设置 → 颜色 → 深色/浅色)→ 页面跟随切换
4. 设置页 →「外观」卡:三态卡片组 + 说明文案随选择变化(「当前始终使用深色主题」等)
5. 走查:工作台/画像/路线图/匹配/简历/设置 各页深色下内容/空/加载/错误四态与文字对比度(dev/tokens 页「深色渲染效果」区可对照色值)

**预期结果**:全站深色一致、无白底残留卡片、语义徽章可读;切回浅色恢复原貌。

### 步骤 S8:Phase 1 回归(对应 A8)

1. 账号甲:画像「更新信息」→ 分析 → 新版本(2.x 链路无退化)
2. 路线图:任务勾选三态、阶段展开、重新生成(3.x)
3. 简历:上传新简历 → 解析 → 核对 → 优化 → 接受/拒绝 → ATS → 导出(4.x 主链路抽查)
4. 工作台 KPI/下一步建议/模块入口正常(5.1)

**预期结果**:Phase 1 全部功能无退化(测试基线 703/703 已绿,此为浏览器抽查)。

## 四、AI 验收(Matching / Coach 真实输出,需真实 Key)

| # | 检查点 | 怎么验 | 判据 |
|---|---|---|---|
| 1 | 拆解与 JD 一致 | S1 粘贴含 3+ 显性要求与 1-2 隐性要求的 JD | requirements 覆盖显性要求,隐性要求揭示区有合理推断(如「需要抗压」未明写) |
| 2 | 映射不编造 | 对比报告证据列与画像/简历 | 每条映射的 userEvidence 能在画像/简历找到出处;无凭空能力 |
| 3 | 分数可解释 | 看匹配度与逐项状态 | 大数字与逐项「达标/接近/不足」分布自洽;无虚假精确度(0-100 整数 + 等级) |
| 4 | 纯英文 JD | 粘贴纯英文 JD | 拆解正常,输出中文 |
| 5 | 无画像降级 | 服务端直测(工程测试已覆盖) | items=[]、overallScore=null、建议为空(「仅拆解不匹配」) |
| 6 | 教练计划预算 | 每周投入 10h → 看各周任务时长 | 每周 ΣestimatedMinutes ≤ 600;13 周连续;milestone 在周内 |
| 7 | P0 矩阵规则 | 看优先级矩阵 | P0 = 重要性≥4 且差距大;排序按重要性×差距 |
| 8 | 资源标注 | 看资源卡 | 全部标 free/paid;免费置前;无虚构付费课程 |
| 9 | 稳定性 | 同一 JD 连续匹配 2 次 | 匹配度与逐项状态大致一致(允许小幅波动) |
| 10 | 失败反馈 | mock 环境提交 | 友好错误 + 重试,不显示裸 JSON |

## 六、通过标准

1. **P0 全部通过**。其中 P0-1/P0-2 在 mock 模式下可走通链路(数据为演示夹具);「AI 分析质量」验收需真实 DeepSeek Key,不配 Key 时该项降级为「遗留验证项」(与阶段 2 先例一致),其余 P0 必须全部通过。
2. **P1 无阻塞性问题**:允许个别未过但须记录。
3. **无严重数据错误**:JobMatch 单行匹配/教练双管线数据不互相覆盖;版本删除不影响原简历;旧画像版本不可变。
4. **核心链路未失效**:JD → 匹配 → 教练 → 落库 → 渲染 → 纠偏重算;AI 失败有明确反馈与恢复路径。
5. **无功能退化**:Phase 1(画像/路线图/简历/工作台)全量回归通过。
6. **不要求**:6.7 微信登录(暂缓)、6.10 与阶段 7(不执行)、真实 LLM 稳定性指标(需多次真实调用积累)。
