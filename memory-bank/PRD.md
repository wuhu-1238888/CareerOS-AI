> 版本：v1.0 | 最后更新：2026-07-25 | 状态：MVP 定义阶段

## 一、产品概述

### 1.1 产品定义

CareerOS AI 是一个基于 AI Agent 架构的职业成长操作系统（Web 应用）。

它帮助用户完成：**自我认知 → 方向探索 → 成长规划 → 简历优化** 的核心链路。

MVP 聚焦三个模块：
- **Career Profile** — AI 生成用户职业数字画像
- **Career Navigator** — AI 生成个性化职业成长路线图
- **Resume Intelligence Engine** — 基于职业画像的深度简历优化

### 1.2 目标用户

详见 [user-persona.md](./user-persona.md)。核心服务四类人群：

| 优先级 | 用户群 | MVP阶段占比预估 |
|--------|--------|-----------------|
| P0 | 应届毕业生 | 40% |
| P1 | 大学生（大二-大四） | 35% |
| P2 | 0-3年职场新人 | 20% |
| P3 | 转行人群 | 5% |

### 1.3 产品目标（MVP）

| 目标类型 | 具体目标 |
|----------|----------|
| **核心价值验证** | 用户是否愿意让AI深度理解自己，并接受AI生成的职业建议 |
| **用户行为目标** | 画像完成率 > 60%，路线图采纳率 > 30%，简历优化完成率 > 50% |
| **体验目标** | 首次使用到获得第一个有价值输出的时间 < 5分钟 |
| **技术验证** | 多Agent架构在Web应用中的可行性 |

### 模块1：Career Profile（职业数字画像）

#### 3.1.1 功能概述

用户输入个人背景信息，AI 分析并生成一份结构化的职业数字画像。这是整个系统的"用户理解层"，是所有下游功能的数据基础。

#### 3.1.2 用户流程

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  进入首页  │ →  │  输入背景  │ →  │ AI 分析中  │ →  │  查看画像  │ →  │  确认/修正 │
│           │    │  (分步表单) │    │  (进度动画) │    │  (可视化)  │    │  (交互调整) │
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
```

#### 3.1.3 用户输入项

| 字段 | 类型 | 是否必填 | 说明 |
|------|------|----------|------|
| 教育背景 | 下拉+输入 | 必填 | 学校、专业、学历、毕业时间 |
| 技能标签 | 多选+自定义 | 必填 | 从技能库选择或自由输入，按熟练度分级 |
| 实习/工作经历 | 结构化文本 | 推荐 | 公司、岗位、时长、主要职责 |
| 项目经历 | 结构化文本 | 推荐 | 项目名称、角色、成果 |
| 职业兴趣方向 | 多选 | 推荐 | 从行业/职能库中选择感兴趣的方向 |
| 职业目标 | 输入 | 可选 | 用户已有的目标岗位（如无，AI会推荐） |

**设计原则**：
- 分步采集，每步3-5个字段，避免一次性输入过多导致放弃
- 必填项控制在最少（学历 + 专业 + 技能），降低进入门槛
- 每一步给出"为什么我们需要这个信息"的解释
- 支持"先粗略填写 → 后续完善"的渐进式画像构建

#### 3.1.4 AI 输出内容

| 输出项 | 内容说明 | 展示形式 |
|--------|----------|----------|
| **职业画像概要** | 2-3句话概括用户职业特征 | 文字卡片 |
| **优势分析** | 列举3-5个当前突出优势 | 列表 + 标签 |
| **潜在职业方向** | 推荐2-4个适合的职业方向 | 卡片列表，含匹配度百分比 |
| **能力雷达图** | 多维度能力评估（产品、技术、数据、沟通、项目等） | 雷达图 |
| **发展建议** | 针对核心不足的简要提升建议 | 文字 |

#### 3.1.5 交互细节

- 输入阶段提供"示例"引导（如：技能输入区展示"Java / Python / Figma / 数据分析..."）
- AI分析阶段展示进度动画，告知"正在分析你的职业画像..."
- 画像结果页支持"这不是我"反馈按钮，允许用户纠偏
- 画像可分享（生成图片卡片，用于社交媒体传播，同时带来新用户）

#### 3.1.6 成功指标

| 指标 | 目标值 |
|------|--------|
| 画像生成完成率（开始填写→生成画像） | > 60% |
| 平均完成填写时间 | < 3分钟 |
| 画像结果"认可率"（不点击纠偏） | > 75% |
| 分享率（生成分享卡片的用户占比） | > 15% |

### 模块2：Career Navigator（职业成长导航）

#### 3.2.1 功能概述

基于用户的职业画像和目标方向，AI 生成一条分阶段的职业成长路线图。每个阶段包含学习内容、实践项目、能力目标和时间预估。

#### 3.2.2 用户流程

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  选择目标  │ →  │ AI 生成   │ →  │  查看路线  │ →  │  开始执行  │
│  职业方向  │    │  成长路线  │    │  (时间线)  │    │  (标记任务) │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
```

**前置条件**：用户已完成 Career Profile（或跳过来直接选择目标方向）。

#### 3.2.3 输入

| 输入来源 | 说明 |
|----------|------|
| 职业画像数据 | 自动从 Career Profile 继承（教育的背景、技能、优势/不足） |
| 目标职业方向 | 从画像推荐的2-4个方向中选择，或用户自行输入 |
| 时间投入 | 用户可投入的学习时间（每周X小时） |
| 当前阶段 | 用户自评当前所处阶段（完全新手 / 有一定基础 / 接近入门） |

#### 3.2.4 AI 输出内容

**路线图分为3-4个阶段**，每阶段包含：

| 阶段要素 | 说明 |
|----------|------|
| 阶段名称 | 如"基础构建期（0-3个月）" |
| 阶段目标 | 该阶段结束时用户应达到的状态 |
| 学习内容 | 具体的学习主题列表（如"LLM基础原理""Prompt Engineering"） |
| 实践项目 | 可执行的项目建议（如"用LangChain构建一个文档QA系统"） |
| 资源推荐 | 推荐的学习资源（课程、文章、工具，注明免费/付费） |
| 能力检查点 | 该阶段结束时的自检标准（如"能独立完成RAG pipeline搭建"） |
| 预估时间 | 在给定每周投入时间下的预估完成时间 |

#### 3.2.5 展示形式

- **主视图**：纵向时间线，展示阶段递进关系
- **每个阶段可展开**：查看详细学习内容和任务
- **进度追踪**：支持对任务进行勾选标记（"待开始 / 进行中 / 已完成"）
- **全局概览**：顶部显示"从XX到XX的X个月成长路径"

#### 3.2.6 交互细节

- 用户可对路线图内容进行反馈（"这个任务对我太难了"/"我已经会了"），AI据此调整
- 支持切换目标方向后重新生成路线图
- 路线图可导出为图片或PDF

#### 3.2.7 成功指标

| 指标 | 目标值 |
|------|--------|
| 路线图生成完成率（选择目标→生成路线图） | > 80% |
| 路线图"开始执行"率（标记至少1个任务为进行中） | > 30% |
| 路线图满意度（用户反馈"有帮助"） | > 70% |

### 模块3：Resume Intelligence Engine（简历智能引擎）

#### 3.3.1 功能概述

上传现有简历，AI 解析并基于职业画像和目标岗位进行深度优化。不是简单润色文字，而是根据用户职业方向重新表达经历。

#### 3.3.2 用户流程

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│  上传简历  │ →  │ AI 解析   │ →  │  选择目标  │ →  │ AI 优化   │ →  │  查看/导出 │
│  (PDF/Word)│    │  提取信息  │    │  岗位/方向  │    │  简历内容  │    │  简历     │
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
```

**前置条件**：用户已有简历文件，或可以从 Career Profile 数据自动生成初版简历。

#### 3.3.3 输入

| 输入 | 格式 | 说明 |
|------|------|------|
| 原始简历 | PDF / Word / 图片 | 上传解析，或粘贴文本 |
| 目标岗位方向 | 选择 | 从Career Profile推荐方向中选择或输入JD |
| 职业画像数据 | 自动 | 自动关联已有的画像数据 |

#### 3.3.4 AI 处理流程

```
原始简历
    │
    ▼
┌─────────────┐
│  1. 简历解析  │  → 提取：基本信息、教育、技能、经历（工作/项目/实习）
└─────────────┘
    │
    ▼
┌─────────────┐
│  2. 内容理解  │  → 分析：经历的真实含义、可迁移能力、隐藏亮点
└─────────────┘
    │
    ▼
┌─────────────┐
│  3. 画像对比  │  → 关联：将简历内容与用户职业画像交叉验证
└─────────────┘
    │
    ▼
┌─────────────┐
│  4. 方向重写  │  → 优化：根据目标方向重新表达经历（不是改写文字，是重构叙事）
└─────────────┘
    │
    ▼
┌─────────────┐
│  5. 质量检查  │  → 验证：ATS友好性、关键词覆盖、量化成果、可读性
└─────────────┘
```

#### 3.3.5 AI 输出内容

| 输出项 | 说明 |
|--------|------|
| **优化后的简历** | 完整的简历文本，支持复制和导出 |
| **修改对比** | 逐段展示"修改前 → 修改后 → 为什么这样改" |
| **ATS评分** | 针对简历的ATS友好度评分（关键词、格式、可解析性） |
| **亮点提取** | AI识别的简历亮点（用户可能自己没意识到的优势） |
| **改进建议** | 简历还可进一步提升的方向 |

#### 3.3.6 核心改写逻辑示例

| 原始表达 | AI改写 | 改写逻辑 |
|----------|--------|----------|
| "负责校园公众号日常运营" | "通过用户行为分析和A/B内容实验，将公众号互动率提升40%" | 从"做了什么"转为"用什么方法 → 带来什么结果" |
| "参与XX小程序开发" | "作为核心开发成员，主导了XX小程序的支付模块设计与实现，支撑月均交易额XX万" | 从模糊参与转为具体角色+量化成果 |
| "管理供应商合同" | "统筹管理20+供应商全生命周期合同，建立标准化流程将审批效率提升50%" | 从日常操作转为系统性能力 |

#### 3.3.7 交互细节

- 上传简历后的解析过程展示进度
- 解析结果允许用户核对修正（AI可能识别不准的地方）
- 优化结果以"修改对比"视图展示（左旧右新），让用户理解改了什么
- 支持对单条优化结果"接受/不接受"，而非全盘接受或拒绝
- 支持导出为PDF和Word格式
- 支持为同一个用户生成多个目标方向的简历版本
- 结果页提供「重新上传简历」入口:点击进入「上传新简历」视图(明确提示「本次上传会新增一份独立简历,不会修改或删除已有简历」),每次上传新建简历记录,旧简历及其解析结果、优化版本全部保留,上传完成后自动切换到新简历
- 支持多份简历并存:设置页「简历文件管理」列出全部简历,每份可「查看」(打开该简历的解析/优化数据)/下载/删除;页面级提供「+ 新增简历」入口(与结果页「重新上传简历」同一新建流程)。简历卡片上不提供「更换/替换」入口,换简历 = 新增一份

#### 3.3.8 成功指标

| 指标 | 目标值 |
|------|--------|
| 简历上传解析成功率 | > 90% |
| 优化完成率（上传 → 导出优化版） | > 50% |
| 优化结果接受率（接受>80%的修改建议） | > 60% |
| 单次优化平均耗时 | < 30秒 |

## 四、非MVP功能概述

### 模块4：Job Matching Agent（岗位匹配 Agent）— P1

**核心功能**：用户输入目标JD或选择岗位，AI分析匹配度并输出差距报告。

| 输入 | 输出 |
|------|------|
| 目标JD（粘贴或选择） | 匹配度评分（百分比） |
| 用户画像数据 | 逐项能力对比（雷达图） |
| — | 优势匹配项 + 技能缺口列表 |
| — | 针对该岗位的简历优化建议 |
| — | 提升匹配度的行动建议 |

### 模块5：Skill Gap Analyzer（技能差距分析）— P1

**核心功能**：将目标岗位的能力要求与用户当前能力做系统对比，生成提升计划。

| 输入 | 输出 |
|------|------|
| 目标岗位（可多个） | 多维能力雷达图（用户 vs 目标要求） |
| 用户画像数据 | 关键技能差距排序（按重要性和紧迫度） |
| — | 90天能力提升计划（按周） |
| — | 推荐学习资源 |

### 模块6：Interview Agent（AI面试Agent）— P2

**核心功能**：基于用户简历和目标岗位的个性化模拟面试。

| 输入 | 输出 |
|------|------|
| 用户简历 + 目标岗位 |个性化面试问题列表 |
| 面试类型（行为面/技术面/案例面） | AI 语音/文字提问 |
| — | 实时回答评估（内容质量、表达逻辑） |
| — | 面试后综合评估报告 |
| — | 改进建议 |

```
回访到达

    ├──→ 更新信息 → 画像重新生成

    ├──→ 创建新简历版本 → 针对新目标的简历优化
    └──→ 查看进度 → 能力变化追踪
```

## 九、AI Agent 架构映射

目前定义了5个专业Agent，MVP阶段启用前3个：

| Agent | 负责模块 | MVP状态 | 核心职责 |
|-------|---------|---------|----------|
| **Profile Agent** | Career Profile | ✅ 启用 | 分析用户背景，生成职业画像和能力评估 |
| **Navigator Agent** | Career Navigator | ✅ 启用 | 生成个性化职业成长路线图 |
| **Resume Agent** | Resume Intelligence | ✅ 启用 | 简历解析、内容重写、ATS优化 |
| **Matching Agent** | Job Matching | 🔜 P1 | 岗位要求解析与匹配度分析 |
| **Coach Agent** | Skill Gap Analyzer | 🔜 P1 | 技能差距对比与提升计划生成 |
| **Interview Agent** | Interview Agent | 🔜 P2 | 个性化模拟面试与评估 |

Agent之间数据流转：
```
Profile Agent → (画像数据) → Navigator Agent → (路线图数据)
                            → Resume Agent → (简历优化)
                            → Matching Agent → (岗位匹配) [P1]
                            → Coach Agent → (技能提升) [P1]
                            → Interview Agent → (模拟面试) [P2]
```

## 十、版本路线图

### Phase 1：MVP（当前阶段）

**范围**：Career Profile + Career Navigator + Resume Intelligence Engine

**核心验证**：
- 用户是否愿意让AI深度理解自己
- AI生成的职业建议是否足够有价值
- 多Agent架构是否可行

**不包含**：
- 岗位匹配（Job Matching）
- 技能差距分析（Skill Gap Analyzer）※ 基础能力雷达在Profile中保留
- AI面试（Interview Agent）
- 微信登录（先做邮箱）
- 移动端适配（先做PC Web）

### Phase 2：增长期

**新增功能**：Job Matching + Skill Gap Analyzer
**增强功能**：Resume Intelligence增加多版本管理、Profile增加能力变化追踪
**体验提升**：性能优化、移动端适配
**数据接入**：岗位JD数据源接入

### Phase 3：平台期

**新增功能**：Interview Agent
**生态建设**：用户成长数据报告、企业端匹配接口
**数据智能**：基于用户成长数据优化推荐模型

## 十一、风险与假设

### 核心假设

| 假设 | 验证方式 |
|------|----------|
| 用户愿意花3-5分钟输入个人背景信息 | 追踪表单完成率 |
| AI生成的职业建议与用户预期吻合度高 | 追踪画像"认可率" |
| 简历深度优化（重写经历）的价值>简单润色 | A/B测试对比 |
| 用户存在"长期职业成长"需求，而非仅"快速求职" | 追踪留存率 |

### 关键风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| AI分析结果质量不稳定 | 用户信任度下降 | 允许用户纠偏；持续优化Prompt；建立质量评估机制 |
| 用户输入信息不完整 | AI分析不够个性化 | 分步引导+示例；先基于最少信息给出初步分析 |
| LLM调用成本过高 | 无法免费提供核心体验 | 设计免费额度+付费模式；优化Prompt减少Token消耗 |
| 竞品快速跟进 | 差异化优势缩小 | 聚焦数据积累和个性化深度，建立切换成本 |
