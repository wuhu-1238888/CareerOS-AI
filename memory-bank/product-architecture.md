> 版本：v1.0 | 最后更新：2026-07-26

## 一、产品架构总览

### 1.1 架构全景图

CareerOS AI 由 **三层能力架构** + **一个数据底座** + **一组 AI Agent** 组成。

```
┌──────────────────────────────────────────────────────────────────────┐
│                        用户触点层                                    │
│                                                                      │
│   Web 应用    │   个人Dashboard    │   功能入口    │   结果展示       │
│                                                                      │
├──────────────────────────────────────────────────────────────────────┤
│                        核心能力层                                    │
│                                                                      │
│  ┌────────────┐  ┌──────────────┐  ┌──────────────────┐             │
│  │ ① Career   │  │ ② Career     │  │ ③ Resume         │  ← MVP     │
│  │   Profile  │  │   Navigator  │  │   Intelligence   │             │
│  └─────┬──────┘  └──────┬───────┘  └────────┬─────────┘             │
│        │                │                    │                       │
│  ┌─────┴──────┐  ┌──────┴───────┐  ┌────────┴─────────┐             │
│  │ ④ Job      │  │ ⑤ Skill Gap  │  │ ⑥ Interview      │  ← 未来   │
│  │   Matching │  │   Analyzer   │  │   Agent          │             │
│  └────────────┘  └──────────────┘  └──────────────────┘             │
│                                                                      │
├──────────────────────────────────────────────────────────────────────┤
│                        数据底座层                                    │
│                                                                      │
│  用户职业画像数据    │    能力模型    │    职业路径库    │   简历库   │
│                                                                      │
├──────────────────────────────────────────────────────────────────────┤
│                        AI Agent 层                                   │
│                                                                      │
│  Profile Agent  │  Navigator Agent  │  Resume Agent                  │
│  Matching Agent │  Coach Agent      │  Interview Agent               │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

### 1.2 架构设计原则

| 原则 | 说明 | 体现 |
|------|------|------|
| **画像驱动** | 所有功能围绕用户职业画像展开，画像是最核心的数据资产 | 任何模块的输入都关联Profile |
| **模块解耦** | 每个能力模块可独立使用，也可串联成完整链路 | 用户可直接上传简历，也可从Profile开始 |
| **数据流转** | 上游模块的分析结果自动成为下游模块的输入 | Profile → Navigator → Resume |
| **渐进智能** | 用户使用越多，AI对用户的理解越深，建议越精准 | 画像随使用持续更新 |
| **Agent化** | 每个核心能力由独立的AI Agent驱动，各司其职 | 6个Agent各有专精 |

## 二、核心能力层

---

### 2.1 ① Career Profile — 职业数字画像

**定位**：整个系统的"用户理解层"，是所有下游能力的数据源头。

```
用户输入                     AI 分析过程                      输出
───────                    ────────────                    ────
教育背景  ─┐
技能标签  ─┤           ┌──────────────┐                 职业画像概要
项目经历  ─┼──────────→│  Profile     │─────────────→  优势分析
实习经历  ─┤           │  Agent       │                 职业方向推荐
兴趣方向  ─┤           └──────────────┘                 能力雷达图
职业目标  ─┘                                          发展建议
```

**能力描述**：

| 子能力 | 做什么 | 用户价值 |
|--------|--------|----------|
| 背景信息结构化 | 将用户零散输入整合为标准化的职业画像 | 让AI"理解"用户 |
| 能力评估 | 多维度分析用户当前能力水平 | 让用户"看清自己" |
| 方向推荐 | 基于背景和能力推荐2-4个可行职业方向 | 解决"我不知道该做什么" |
| 差距分析 | 对比用户当前状态与推荐方向的差距 | 让用户知道"我还差什么" |

**与其他模块的关系**：

- → **Navigator**：画像中的推荐方向直接成为规划目标
- → **Resume Intelligence**：画像中的能力分析指导简历改写方向
- → **Matching Agent**：画像作为匹配计算的基础
- → **Skill Gap Analyzer**：画像中的能力基线是对比起点

**用户使用场景**：

- 首次使用：完整填写信息，获得初始画像
- 定期更新：增加新技能/经历后更新画像
- 方向探索：切换目标方向后查看匹配度变化

### 2.2 ② Career Navigator — 职业成长导航

**定位**：将"目标方向"翻译成"可执行的成长路线图"。

```
输入                          AI 分析过程                      输出
────                       ────────────────                  ────
目标职业方向 ─┐
用户当前能力 ─┤         ┌──────────────┐                  阶段1：基础构建
每周可投入时间─┼────────→│  Navigator    │─────────────→   阶段2：能力提升
学习偏好     ─┘         │  Agent        │                  阶段3：实战积累
                        └──────────────┘                  阶段4：求职准备
                                                         每阶段含：
                                                         · 学习内容
                                                         · 实践项目
                                                         · 资源推荐
                                                         · 检查点
```

**能力描述**：

| 子能力 | 做什么 | 用户价值 |
|--------|--------|----------|
| 路径拆解 | 将"成为XX"拆解为3-4个递进阶段 | 大目标变成小台阶 |
| 内容规划 | 每阶段规划具体学习内容和实践项目 | 知道"学什么" |
| 时间预估 | 根据用户时间投入估算每阶段所需时长 | 建立合理预期 |
| 进度追踪 | 支持任务状态标记，追踪成长进度 | 让进步"看得见" |

**核心设计理念**：

不是给用户一个"课程表"，而是给用户一个"成长策略"。

```
差的设计：               好的设计：
"学习Python"             "第1-2周：用Python完成一次数据分析项目，
                         产出物——一份可视化的行业分析报告，可以放入作品集"
```

**与其他模块的关系**：

- ← **Career Profile**：用户的起点数据
- → **Skill Gap Analyzer**：路线图中的阶段目标是差距分析的输入
- → **Resume Intelligence**：路线图中的项目经历可以成为简历素材

### 2.3 ③ Resume Intelligence Engine — 简历智能引擎

**定位**：不只是"改简历"，而是基于对用户的深度理解，重新构建用户的职业叙事。

```
输入                          AI 分析过程                      输出
────                       ────────────────                  ────
                          ┌──────────────┐
原始简历 ─────────────────→│  简历解析     │─────────────→  结构化信息
                          └──────┬───────┘
                                 │
                          ┌──────┴───────┐
用户画像数据 ─────────────→│  内容理解     │─────────────→  能力提取
                          └──────┬───────┘
                                 │
                          ┌──────┴───────┐
目标岗位方向 ─────────────→│  方向重写     │─────────────→  优化简历
                          └──────┬───────┘
                                 │
                          ┌──────┴───────┐
                          │  质量检查     │─────────────→  ATS评分
                          └──────────────┘              修改对比
```

**能力描述**：

| 子能力 | 做什么 | 用户价值 | AI思考方式 |
|--------|--------|----------|------------|
| 简历解析 | 提取结构化信息 | 省去手动填写 | 识别简历中的实体和关系 |
| 内容理解 | 分析经历背后的真实能力 | 发现隐藏亮点 | "这段经历体现了什么能力？" |
| 方向重写 | 根据目标重新表达经历 | 提高匹配度 | "如果目标是XX，这段经历应该强调什么？" |
| 质量检查 | 评估ATS友好性、可读性 | 确保能被筛选到 | "简历筛选系统会如何解读这份简历？" |

**核心差异化**：

| 传统AI简历工具 | CareerOS Resume Intelligence |
|---------------|---------------------------|
| 你写"公众号运营"→ 润色为"负责公众号日常内容运营" | 你写"公众号运营"→ 分析你做了什么、用了什么方法、带来什么结果 → 重新表达 |
| 通用优化，所有人改出来差不多 | 基于你的画像和目标方向，千人千面 |
| 改完即结束 | 改完的简历和你的画像、路线图关联，持续迭代 |

**与其他模块的关系**：

- ← **Career Profile**：提供用户能力标签和方向偏好
- ← **Career Navigator**：路线图中的实践经验可作为简历素材
- → **Job Matching**：优化后的简历可用于匹配度计算

### 2.4 ④ Job Matching Agent — 岗位匹配（P1）

**定位**：连接"用户能力"和"市场要求"的桥梁。不只是看关键词匹配，而是理解JD背后的真实需求。

```
输入                          AI 分析过程                      输出
────                       ────────────────                  ────
                          ┌──────────────┐
目标JD ──────────────────→│  需求拆解     │─────────────→  岗位能力要求清单
                          └──────┬───────┘
                                 │
                          ┌──────┴───────┐
用户画像数据 ─────────────→│  能力映射     │─────────────→  逐项匹配结果
                          └──────┬───────┘
                                 │
                          ┌──────┴───────┐
                          │  差距计算     │─────────────→  匹配度评分
                          └──────┬───────┘                 优势/不足
                                 │
                          ┌──────┴───────┐
                          │  建议生成     │─────────────→  提升建议
                          └──────────────┘
```

**能力描述**：

| 子能力 | 做什么 | 用户价值 |
|--------|--------|----------|
| JD需求拆解 | 将岗位描述拆解为结构化能力要求（必备/加分/隐性） | 理解JD"真正要什么" |
| 能力映射 | 将用户画像中的能力逐项映射到JD要求 | 看清匹配点 |
| 差距计算 | 量化每项能力的差距 | 知道自己差在哪、差多少 |
| 提升建议 | 针对差距给出可操作的改进建议 | 知道怎么"补齐" |

---

### 2.5 ⑤ Skill Gap Analyzer — 技能差距分析（P1）

**定位**：将模糊的"我够不够格"变成精确的"我在哪些维度差多少，怎么补"。

```
输入                          AI 分析过程                      输出
────                       ────────────────                  ────
                          ┌──────────────┐
目标岗位要求 ─────────────→│  能力标准建模  │─────────────→  目标能力基准线
                          └──────┬───────┘
                                 │
                          ┌──────┴───────┐
用户当前能力 ─────────────→│  差距量化     │─────────────→  雷达图对比
                          └──────┬───────┘                 差距排序
                                 │
                          ┌──────┴───────┐
                          │  提升规划     │─────────────→  90天提升计划
                          └──────────────┘                 每周任务
                                                          推荐资源
```

**能力描述**：

| 子能力 | 做什么 | 用户价值 |
|--------|--------|----------|
| 能力标准建模 | 为每个目标岗位建立多维能力标准 | 让用户知道"标杆在哪" |
| 差距量化 | 用户 vs 标准逐项对比，可视化展示 | 让差距"看得见" |
| 优先级排序 | 按"重要性×差距大小"排序优化顺序 | 知道先补什么 |
| 提升规划 | 生成以周为单位的可执行提升计划 | 知道怎么补 |

---

### 2.6 ⑥ Interview Agent — AI面试（P2）

**定位**：基于用户真实背景和岗位要求，提供高度个性化的模拟面试体验。

```
输入                          AI 分析过程                      输出
────                       ────────────────                  ────
用户简历 ─────┐
目标岗位 ─────┤         ┌──────────────┐                  个性化面试问题
项目经历 ─────┼────────→│  面试生成     │─────────────→   逐题AI提问
用户画像 ─────┘         └──────┬───────┘
                               │
                        ┌──────┴───────┐
用户回答 ──────────────→│  实时评估     │─────────────→  回答评分
                        └──────┬───────┘                改进建议
                               │
                        ┌──────┴───────┐
                        │  综合报告     │─────────────→  面试分析报告
                        └──────────────┘                能力评价
                                                       重点改进项
```

**能力描述**：

| 子能力 | 做什么 | 用户价值 |
|--------|--------|----------|
| 个性化出题 | 根据简历和岗位生成针对性问题，不是通用题库 | 面试题跟真实面试一样"量身定制" |
| 实时评估 | 对回答进行内容质量和表达逻辑评估 | 即时知道答得好不好 |
| 改进建议 | 给出每道题的优化回答方向 | 知道下次怎么说更好 |
| 综合分析 | 生成面试表现的全局评估 | 知道自己的面试短板在哪 |

```
模块               所需上游数据                      产出数据
────               ────────────                     ────────

                   (不依赖其他模块)                  能力标签
                                                   推荐方向

Career Navigator   ← Profile.推荐方向              成长路线图
                   ← Profile.能力标签               阶段任务
                                                   进度数据

Resume             ← Profile.能力标签               优化后简历
Intelligence       ← Profile.推荐方向               简历分析报告
                   ← Navigator.项目经历(可选)

Job Matching       ← Profile.能力标签               匹配度报告
                   ← Profile.推荐方向               岗位建议
                   ← Resume.优化简历(可选)

Skill Gap          ← Profile.能力标签               能力差距报告
Analyzer           ← Matching.岗位要求              提升计划
                   ← Navigator.阶段目标(可选)

Interview          ← Resume.优化简历                面试结果
Agent              ← Profile.能力标签               面试报告
                   ← Matching.岗位要求(可选)
```

### 3.3 模块间的三种使用模式

**模式一：完整链路（推荐）**

```
Career Profile → Career Navigator → Resume Intelligence → Job Matching → Interview
```

用户从0开始，系统逐步引导，完成全链路。适合方向不明确的用户。

**模式二：跳入式**

```
直接使用 Resume Intelligence（上传简历 → 优化 → 导出）
```

用户有明确目标，只需要简历优化。但系统会建议完成Profile以获得更好的优化效果。

**模式三：回访式**

```
Dashboard → 更新Profile → 查看Navigator进度 → 优化新版本简历
```

回访用户基于已有数据继续成长，追踪变化。

## 四、用户价值闭环

### 4.1 核心价值环路

CareerOS AI 的用户价值不是线性的"用完即走"，而是一个**持续成长的闭环**。

```
                    ┌─────────────────────────┐
                    │                         │
                    ▼                         │
           ┌──────────────┐                   │
           │  ① 自我认知   │                   │
           │  我是什么样的人 │                   │
           │  我能做什么    │                   │
           └──────┬───────┘                   │
                  │                            │
                  ▼                            │
           ┌──────────────┐                   │
           │  ② 方向发现   │                   │
           │  我适合什么方向 │                   │
           │  目标有多大差距 │                   │
           └──────┬───────┘                   │
                  │                            │
                  ▼                            │
           ┌──────────────┐                   │
           │  ③ 路径规划   │                   │
           │  我该怎么到达   │                   │
           │  分几步走      │                   │
           └──────┬───────┘                   │
                  │                            │
                  ▼                            │
           ┌──────────────┐                   │
           │  ④ 能力提升   │                   │
           │  学习+实践     │                   │
           │  缩小差距      │──────────────────┘
           └──────┬───────┘        (回到①更新画像)
                  │
                  ▼
           ┌──────────────┐
           │  ⑤ 价值表达   │
           │  简历优化      │
           │  面试准备      │
           └──────┬───────┘
                  │
                  ▼
           ┌──────────────┐
           │  ⑥ 机会匹配   │
           │  岗位匹配      │
           │  拿到Offer    │
           └──────────────┘
```

### 4.2 每一环的用户故事

| 环节 | 用户心中所想 | CareerOS AI 做什么 | 交付物 |
|------|-------------|-------------------|--------|
| ① 自我认知 | "我不知道自己有什么优势" | 分析背景，提炼能力标签，生成画像 | 职业画像卡片 |
| ② 方向发现 | "我适合做什么" | 基于画像推荐方向，计算匹配度 | 推荐方向列表 |
| ③ 路径规划 | "怎么一步步到达" | 拆解目标为阶段路线图 | 成长路线图 |
| ④ 能力提升 | "我变强了吗" | 追踪学习进度，更新能力评估 | 更新后的画像 |
| ⑤ 价值表达 | "怎么让别人看到我的能力" | 基于画像和目标重写简历 | 优化后简历 |
| ⑥ 机会匹配 | "我能拿到Offer吗" | 岗位匹配分析，模拟面试 | 匹配报告+面试评估 |

### 4.3 闭环价值：为什么用户会回来

```
第一次使用：                第二次使用：                第N次使用：
"看看我能做什么"            "我在按路线图学习，          "我的能力雷达图变了，
                          简历也优化了，              画像匹配度从62%→85%，
                          进度如何？"                该准备面试了"

画像 v1.0                  画像 v1.3                   画像 v3.0
匹配度 62%                 匹配度 74%                  匹配度 85%

用户感知到的价值：
"不是一次性工具，是陪伴我成长的系统"
```

这就是 CareerOS 的核心壁垒——**用户数据越用越厚，AI理解越来越深，价值越用越大**。竞品可以复制功能，但无法复制用户积累的成长数据。

## 五、MVP 产品范围

### 5.1 MVP 范围定义

```
┌─────────────────────────────────────────────────────────────┐
│                      MVP 范围                               │
│                                                             │
│  ┌──────────────────┐  ┌──────────────────┐  ┌───────────┐ │
│  │  Career Profile  │  │ Career Navigator │  │  Resume   │ │
```

### 5.2 MVP 的"做什么"与"不做什么"

| 维度 | MVP 做 | MVP 不做 |

| **Career Navigator** | 选择方向 → 生成路线图 → 阶段展示 | 任务进度追踪（保留手动标记） |
| **Resume Intelligence** | 上传解析 → 方向重写 → 对比展示 → 导出 | 多版本管理、ATS深度评分 |
| **Job Matching** | — | 整个模块延后至Phase 2 |
| **Skill Gap Analyzer** | Profile中保留基础能力雷达图 | 差距排序、90天计划、资源推荐 |
| **Interview Agent** | — | 整个模块延后至Phase 3 |
| **平台能力** | 邮箱注册登录、PC Web | 微信登录、移动端、分享功能 |

## 六、未来扩展路径

### 6.1 Phase 2：补齐求职闭环（Job Matching + Skill Gap）

**新增能力**：
- Job Matching Agent：用户输入JD → AI分析匹配度 → 输出差距报告
- Skill Gap Analyzer：系统对比能力 → 生成90天提升计划

**与MVP的关系**：
- 用户已完成画像和路线图 → 对接岗位匹配更有针对性
- 路线图中的阶段目标 → 成为Skill Gap分析的参照系

**核心验证**：
- 用户在"规划"之后是否有"匹配"需求
- AI生成的技能差距分析和提升计划是否有行动指导力

### 6.2 Phase 3：完善体验闭环（Interview + 数据智能）

**新增能力**：
- Interview Agent：个性化模拟面试 → 实时评估 → 面试报告
- 数据智能层：用户成长数据追踪 → 画像变化可视化 → 路径有效性验证

**核心验证**：
- 模拟面试的个性化程度是否足以与真人模拟区分
- 用户是否愿意长期使用并积累数据

### 6.3 长期演进方向

## 七、关键设计决策

### 7.1 为什么以 Career Profile 为起点

**决策**：所有功能围绕 Profile 展开，Profile 是系统的数据源头。

**原因**：
- 如果用户跳过Profile直接优化简历，AI不知道"这个人是谁"，只能做浅层文字润色
- Profile 是差异化壁垒——竞品可以做一个简历优化工具，但没有用户画像的积累，就无法做深度个性化
- Profile 是"用户切换成本"的来源——用户在Profile中投入的数据越多，越不可能换到另一个工具

### 7.2 为什么模块可以独立使用

**决策**：每个模块有独立入口，同时也支持串联。

**原因**：
- 降低首次使用门槛——用户可以从最需要的功能开始
- 不同用户画像的入口偏好不同：P1（大学生）从Profile开始，P2（应届）从简历开始
- 独立使用的结果质量低于串联使用，这会自然引导用户完成更多模块

### 7.3 为什么选择 Agent 架构

**决策**：每个核心能力由独立的 AI Agent 驱动。

**原因**：
- 每个模块的AI任务差异大（分析画像 vs 规划路径 vs 改写简历），单一Prompt无法兼顾
- Agent化后每个模块可独立迭代优化，互不影响
- 未来可扩展——增加新能力只需增加新Agent
- 产品叙事一致——"多个AI职业顾问共同服务你"比"一个AI做所有事"的感知价值更高
